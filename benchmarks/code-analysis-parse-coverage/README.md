## Reproduce the coverage difference

Use a `compile_commands.json` with one `src/fmt-c.cc` command, `-std=c++17`, the repository's `include` directory and MSVC STL `14.44.35207` as a system include with `-fms-compatibility-version=19.44`. Point `config.cpp.compileCommands` to the database and run `archify code-analysis check <fmt> --language cpp --config <config> --out <output> --json`. With libclang 18.1.1 the STL emits `STL1000`. For the positive control add `-D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH` to the recorded command. This workaround is for the test setup.

| fmt control | Captured file records | Successfully analyzed | Parse errors |
| --- | ---: | ---: | ---: |
| Labs, Clang error | 1 | 1 | 1 |
| Candidate, same error | 1 | 0 | 1 |
| Candidate, parses | 3 | 3 | 0 |

For the Vue replay, run `check <vue> --language ts --out <pre-cxx> --fail-on never` with the old Archify revision, then `check <vue> --language ts --compare <pre-cxx>/findings.json --new-only --out <post-cxx> --json` with the candidate. Use the same absolute source directory. The negative comparison gate and parse-failure gate both retain their existing behavior.

The C++ counts are bounded to the one recorded translation unit and project headers it reached. The Java and Rust checks establish source declaration navigation for the pairs above. They cannot establish whole-repository recall or runtime dispatch.
