# Review corrections

The implementation review of `cc59590559a893a3f6a6784c8297c423065871a4` found four defects in the existing bounded C/C++ model. Adapter revision 4 corrects them without adding macro call targets or cross-unit binding.

| Trigger | Before | Corrected behavior and regression |
| --- | --- | --- |
| A project header is included through a wrapper outside the project root | Definitions referenced an unrecorded file and extraction failed with `extract/schema-invalid` | Registers active project targets before filtering the edge's origin; verifies captured file, TU context, bound target and saved reverse navigation |
| A captured `.ipp/.inl/.tcc/.tpp/.def` is a saved question entry | `task/entry-invalid`, despite valid facts and context | Reuses the captured file inventory; all five suffixes complete saved function questions and reverse navigation |
| A function-like macro shares the target function or member name | The name regex incorrectly admitted `cpp-direct-source` | Checks the callee's source point against Clang's active macro expansions; same-name, qualified, member, alias and wrapper macros stay unknown, while ordinary calls with macro arguments still bind |
| One physical call has different callers across TU macro contexts | A merged unknown call retained the first context's caller | Removes divergent caller identities at merge; preserves an agreed caller when only the callee differs; verifies both saved header contexts |

The affected [C/C++ suite](../../../archify/modules/code-analysis/test/cpp-analysis.test.mjs) contains 12 tests. On the previous implementation, the four affected regressions failed (8 passed, 4 failed, no skips). With the fixes, all 12 passed with no skips using Apple libclang 14 and using the matching bindings/library from `libclang==18.1.1`. A focused ablation replaced the initial recursive callee walk with the first callee child's source location; the macro boundary and ordinary-call controls still passed, so the smaller implementation remains.

The complete module run on canonical Node 22 and libclang 18 executed 652 tests: 636 passed, 0 failed, 16 unrelated optional/platform skips. The C/C++ native tests were executed. The Ubuntu full-regression shard now installs `libclang==18.1.1` and sets `ARCHIFY_CPP_REQUIRED=1`; a missing parser fails these tests rather than silently skipping them. This is a Linux CI execution requirement, not a claim of Windows native-toolchain validation.

## Reference-method correction

The pinned official client's [definition request](https://github.com/microsoft/vscode-cpptools/blob/6c3197862e3cc387c047119887695ab2f3d91bb3/Extension/src/LanguageServer/goToDefinition.ts) and [call hierarchy](https://github.com/microsoft/vscode-cpptools/blob/6c3197862e3cc387c047119887695ab2f3d91bb3/Extension/src/LanguageServer/callHierarchy.ts) are separate features. Its [reference test](https://github.com/microsoft/vscode-cpptools/blob/6c3197862e3cc387c047119887695ab2f3d91bb3/Extension/test/scenarios/MultirootDeadlockTest/tests/reference.test.ts) waits for IntelliSense readiness. The updated fmt harness follows that readiness hook, isolates native caches and removes target-dependent retries.

The official client also has an explicit [TU selection flow](https://github.com/microsoft/vscode-cpptools/blob/6c3197862e3cc387c047119887695ab2f3d91bb3/Extension/src/LanguageServer/extension.ts#L507). Opening a source document before its header does not verify this selection. An A/B macro control reproduced the plugin using the same fallback branch for both requested contexts. Consequently, the fmt report marks every header association as unverified and reports the 24 source-file positive queries separately. Header navigation-location agreement remains recorded; same-context header parity remains unverified.

The broader fixed review matrix comprised 37 positions, plus four call-hierarchy queries using the [official call fixtures](https://github.com/microsoft/vscode-cpptools/tree/6c3197862e3cc387c047119887695ab2f3d91bb3/Extension/test/scenarios/SingleRootProject/assets/call_hierarchy). After these fixes, Archify matched the recorded target definition for all 25 supported positions and kept all 12 conservative boundaries unknown. These reuse the unchanged fixture inputs and the pinned plugin responses from that review; they are separate from the fresh open-source fmt run. Two header macro environments were tested with explicit header commands; this does not certify the plugin's automatic header/TU association. A template call's generic `cpp-unbound` reason remains less specific than `cpp-template`, while its target remains unknown.

The fresh fmt analysis still parses 32/32 units with zero parse failures and produces 57 files, 270 include facts, 4,256 functions, 16,395 call locations and 2,044 bindings. The [raw records and paired report](comparison.json) state the supported location agreement and the unverified contexts; they do not establish whole-project call-graph parity.
