When Archify first spread in September 2026, most articles summarized it in one line: *"a coding-agent skill with 5 diagram types that replaces Mermaid."*

As the repository crosses **[100,000+] GitHub stars** on **`v3.3.2`**, the way developers — and plenty of non-developers — actually use it looks very different from those early write-ups. People are no longer just generating static box-and-arrow diagrams from prompts. They are running **offline repository architecture diagnostics**, exporting **1080p 60 fps walkthrough videos**, attaching **colour-coded change diagrams to GitHub PRs and GitLab MRs**, and turning everyday non-code plans into standalone interactive HTML explainers.

Here is what changed between those early 5-diagram articles and `v3.3.2`, why the entire toolchain stays local and zero-account, and when other tools are still the better choice.

## 1. Ten native diagram types + automatic placement (`layout.mode: "auto"`)

Instead of asking an LLM to hand-author raw SVG coordinates or fragile diagram DSLs, Archify separates semantics from geometry via **typed JSON IR** across **10 native diagram types**:

- Original five: `architecture`, `workflow`, `sequence`, `dataflow`, `lifecycle`
- Added since launch: `erd`, `class`, `tree`, `timeline`, `waterfall`

In `v3.3.x`, new Architecture diagrams support `"layout": {"mode": "auto"}`: the renderer places unpinned components from their relationships using hub-and-peer ordering, straightens shortcuts, reserves label lanes on shared corridors, and cuts avoidable crossings — while keeping any user-supplied positions and routes fixed.

Four newer diagram types are live in the gallery (offline single-file HTML, no login):

- **Class diagram**: [Payment Module Types](https://archify.si/gallery/artifacts/payments.class)
- **Tree diagram**: [Payment Platform Hierarchy](https://archify.si/gallery/artifacts/payment-platform.tree)
- **Timeline diagram**: [Payment Incident Timeline](https://archify.si/gallery/artifacts/payment-incident.timeline)
- **Waterfall diagram**: [Checkout Request Execution](https://archify.si/gallery/artifacts/checkout-request.waterfall)

## 2. Proactive 4-style one-page Explainers (and no codebase required)

Often a single diagram still leaves readers asking *"why?"*. Archify's `.archify.md` **one-page explainers** lead with the conclusion and reasons first, then pair prose, tables, charts, code, and validated diagrams side by side — reading a step highlights the exact matching part of the diagram.

Since `v3.3`, explainers are **proactive by default** for complex flows, diagnoses, comparisons, and plans (switchable back to request-only at any time with `[archify explainer: on-demand]` in your agent's global rules file). And a repository is completely optional:

- Technical deep dives: [Why P99 tail latency spikes while averages stay flat](https://archify.si/cases/explainer/p99-tail-latency) · [What happens before a first HTTPS request? (TLS 1.3)](https://archify.si/cases/explainer/tls-first-visit)
- Everyday decisions & extensible HTML: [First-time apartment rental checklist](https://archify.si/cases/explainer/first-rental) · community-extended [4-day Shanghai CityWalk itinerary](https://archify.si/cases/community/shanghai-citywalk)

## 3. Built-in Architecture Diagnosis (offline static Code Analysis)

Once teams mapped a real repository, the immediate next question was: *"Where are the circular dependencies, tightly coupled modules, complexity hotspots, and layer-rule breaks?"*

**Architecture Diagnosis** is now built directly into the core Skill — no extra packages or cloud accounts required. Ask your agent to run Archify Code Analysis (or invoke it directly from your installed Skill directory):

```sh
node <installed-skill-dir>/bin/archify.mjs code-analysis prepare <repo> --out <dir>
```

It generates one offline `repo.analysis.html` workbench with:

- An interactive **Atlas** (radial dependency star map with sector focus) and a rotatable **3D model**
- Ranked static findings (dependency cycles, coupling, complexity hotspots, layer-rule breaks), each linked to exact source locations with a copyable fix task for your coding agent
- Coverage across **JS/TS, Python, Java, Go, Rust, C, and C++** (Go, Rust, and C/C++ use their local toolchains; Java needs no JDK; JS/TS parser/schema dependencies ship vendored)
- Optional pairing (`--ir <architecture.json>`) so each component in an authored diagram shows its issue count and flags undrawn dependencies, plus offline pinned PR commit review (`v3.3.2`)

**Honest boundary:** Findings come from static analysis of a working-tree revision or pinned commit — not runtime traces or production telemetry.

## 4. Story mode (1080p 60 fps video) & cross-diagram drilldowns

Large diagrams are notoriously hard to present asynchronously in docs, Slack, or RFC reviews. `v3.3.x` adds two lightweight presentation capabilities without turning Archify into a hosted SaaS:

- **Story walkthroughs & video export**: Attach a guided Story mode (draggable timeline, captions, synthesized soundtrack) to any native diagram and export **1080p 60 fps WebM or MP4** video — or use `story validate | svg | stage | video` to choreograph components across multiple diagrams into dual-theme animated SVG, an offline `.stage.html` player, or headless 1080p video.
- **Cross-diagram navigation (drilldowns)**: Link overview nodes to sibling detail HTML files via `href` or `drilldowns`, with header back-navigation via `meta.parentHref` or `?from=`.

## 5. Visual PR / MR walkthroughs (`archify-pr` now bundled by default)

In `v3.3.2`, the **`archify-pr`** companion Skill is included in the default Skills install from `archify.si`.

Instead of burying architectural shifts inside 800-line diffs, `pr preflight | validate | build | attach` draws change marks natively across all 10 diagram types using a **"colour means change"** visual model (neutral unchanged nodes/edges, dotted removed elements, clean badges) and attaches light/dark diagrams to **GitHub PRs** or **GitLab MRs**. By default it only offers diagrams for material diffs.

## Validation boundaries & when another tool fits better

Every native diagram runs through `archify finalize` (schema checks, layout/route clearance checks, and headless real-browser checks by default; explainers run structural and delivery checks by default, with browser checks on demand via `--browser-check`). Automated checks verify structure and measured geometry — they do **not** replace perceptual visual review or prove runtime behavior in production.

And Archify is not trying to replace every diagram tool:

- **Mermaid**: still the lightest choice for a small (<15 node) diagram embedded inline in a GitHub README.
- **Excalidraw (+ MCP)**: better when several people need real-time freehand whiteboarding.
- **PlantUML / D2 / LikeC4**: better for strict text-diff CI pipelines or repo-wide C4 DSL modeling.
- **Eraser.io**: better when you want a managed multi-user SaaS workspace with cloud permissions.

Full tool comparison and honest limits: **[archify.si/compare](https://archify.si/compare)**.

## 一、为什么放弃让大模型裸写 Mermaid？类型化 JSON IR + 确定性校验

在 README 里塞一张 10 个节点以内的小流程图，Mermaid 依然是最轻的方案。但一旦节点超过 20 个，让大模型直接裸写 Mermaid 语法或原始 SVG，本质上是把“理解业务语义”和“计算二维几何排布”硬耦合在一步里，结果往往是连线交叉穿模、文字截断、且输出的是无法交互下钻的静态图。

Archify 把这两件事彻底拆开：
1. **Agent 只负责语义建模**：输出**类型化 JSON IR**（涵盖 10 种原生图型）或 `.archify.md`（一页式解答草稿）。
2. **本地确定性引擎负责布局与门禁**：`finalize` 流水线统一完成 Schema 校验、自动布局（`layout.mode: "auto"`）、正交防穿模路由，并对原生图表默认跑真实无头浏览器渲染检查（Explainer 默认跑结构与交付校验，按需加 `--browser-check`），最终产出一个**双击即可离线打开的单文件 HTML + 可版本化源稿**。

## 三、内置离线架构诊断（Code Analysis）：7 种语言、3D 依赖星图与可复制修复任务

真实代码库画完架构图后，研发最常追问的是：“循环依赖藏在哪？哪些模块耦合最重？重构从哪切入？”

`v3.3` 将 **Architecture Diagnosis（架构诊断）**直接内置进核心 Skill，无需额外装插件。平时直接让 Agent 跑诊断即可；如果要手工调用 CLI，从已安装的 Skill 目录运行并传入目标仓库路径：

```bash
node <已安装-skill-目录>/bin/archify.mjs code-analysis prepare <repo> --out <dir> --locale zh-CN
```

运行后会产出一个单文件离线诊断工作台 `repo.analysis.html`：
- **径向依赖星图（Atlas，支持扇区聚焦）+ 可旋转 3D 模型**
- **按优先级排序的静态发现**：循环依赖、模块耦合、复杂度热点、分层规则违规，每一条直连源码位置，并附带可直接复制交回给 Agent 执行的修复任务单
- **语言覆盖**：JS/TS、Python、Java（无需 JDK）、Go、Rust、C、C++（Go、Rust、C/C++ 需本机具备对应工具链；JS/TS 解析依赖已内嵌）
- **架构图联动 & 离线 PR 提交复核（`v3.3.2`）**：传入 `--ir <architecture.json>` 后，架构图每个组件直接标注问题数并标出漏画的真实依赖；`v3.3.2` 进一步支持对固定 PR 提交做离线架构诊断复核。

> 边界说明：诊断结论来自单次工作区或固定提交的静态分析，不代表生产运行时链路追踪或故障证明。

## 四、Story 模式 1080p 60fps 视频导出 + 多图双向钻取

为了解决大图在异步评审、技术分享或文档里“读者不知道先看哪”的痛点：
- **Story 导览与视频导出**：任意原生图均可附加带拖拽时间轴、字幕和合成音轨的 Story 模式，并直接导出 **1080p 60fps 视频（WebM / MP4）**；也可通过 `story validate | svg | stage | video` 编排多张图生成双主题动态 SVG、离线 `.stage.html` 舞台页或无头 1080p 视频。
- **多图钻取跳转（Cross-Diagram Drilldowns）**：通过节点 `href` 或 `drilldowns` 从总览图直接钻取到同目录子图 HTML，并借助 `meta.parentHref` 或 `?from=` 自动提供顶部返回按钮。

## 五、PR / MR 变更可视化（`v3.3.2` 起默认捆绑 `archify-pr`）

几百行代码 diff 里，架构层面的新增、删除和耦合变化极难一眼看穿。`v3.3.2` 将伴随 Skill **`archify-pr`** 直接纳入官方默认安装，全 10 种图型支持原生变更标注，并采用**“色彩即变更”**的克制视觉设计（未改动节点与连线保持中性、删除元素用虚线、清晰角标），可直接把深浅双主题变更图解附到 **GitHub PR** 或 **GitLab MR**（默认仅在实质性代码变更时主动提示）。

## 二、逐个拆解：每一款工具的真正主场与短板

### 1. draw.io（diagrams.net）：传统手动画图的“免费开源天花板”
- **什么时候选它**：你不需要 AI 代画，只想打开网页（或桌面端）自由拖拽标准流程图、UML、云架构图标、组织架构图，且追求完全免费、数据保存在本地或网盘。
- **真实短板**：节点超过二三十个以后，大量时间会花在对齐框体、绕开交叉箭头、微调连线折点上；改需求时的维护成本全靠人手扛。

### 2. ProcessOn：国内团队与日常办公最省心的在线模板库
- **什么时候选它**：你在国内网络环境下办公，需要中文界面、海量现成流程图/思维导图/泳道图模板，并且经常直接发在线链接给同事看。
- **真实短板**：免费版对文件数量和云空间有严格限制；同样属于人工拖框模式，面对真实代码仓库或复杂系统演进时无法自动关联源码证据。

### 3. Mermaid：Markdown 文档内嵌小图的绝对王者
- **什么时候选它**：图只有 5–15 个节点，必须直接嵌在 GitHub README、飞书/语雀/Notion 或博客 Markdown 代码块里，且方便人在 Git Diff 里随手改两行文字。
- **真实短板**：一旦业务链路变长，连大模型自己写 Mermaid 也经常触发语法报错或“蜘蛛网式连线交叉”；而且读者看到的仍是静态 SVG，没法点击某个节点高亮它的上下游链路。

### 4. Excalidraw（含 Excalidraw MCP）：多人白板头脑风暴首选
- **什么时候选它**：开会时需要几个人同屏一边讲一边画手绘风草图，或者希望通过 MCP 让 AI 在一个可随时手改的无限画布上起草框架。
- **真实短板**：偏随性草图定位，做正式评审报告、代码级依赖诊断或分步骤图文联动讲解不是它的强项。

### 5. Archify（`v3.3.2`，开源突破 `[10 万+]` Star）：面向 AI Agent 的“结构化交互图 + 一页式解答 + 架构诊断”工具链
