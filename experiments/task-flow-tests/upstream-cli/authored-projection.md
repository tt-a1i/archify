# Public review projection: authored input

`inputs/shared-review.json` is a manually authored projection of the unchanged `../input/mapping.json` and `../flows.json` into the public task-view review format pinned at gtindo/task-view `a3fa21767bfaeb3077fdda08bddb7249366caa93`. It is a proposed input, not a validation receipt. The placeholder `<REPOSITORY_ROOT>` must be replaced in a separate local copy with an absolute or review-relative path of a repository containing the historical objects. The commits array contains the head `ed62bfefaf490e831259261fdc12f985267590fb`, whose parent is base `de004edf47228b6134fd3d29ef91cd5e010c867b`.

Five node IDs, labels, why texts and exact file/line ranges are retained. Base references use `deleted` and omit `at`, so the pinned resolver reads the initial state; head references also omit `at`, so it reads the final state, with regression `added`/`test` and the two other head nodes `modified`/`code`. The first draft and its original explanation are preserved byte-for-byte in `inputs/initial/`: explicit base `at` caused `bad_at` because base was not listed as a change commit; explicit head `at` skipped change attribution and produced unmentioned-hunk findings. In `internal/engine/refs.go`, `resolveState` selects initial for deleted and final otherwise when `at` is absent, while `checkByType` enables node change checks only when `ref.At` is empty. This is a correction of the authored input, not an upstream defect. These change/kind assignments are the projection author's interpretation, not independent Git findings. Source excerpts, prior hashes, hunk accounting and reference-match status remain in the original mapping; they are not imported as validation results.

Four edges retain their endpoints. The original `声明：测试关联` becomes the public `tests` kind so the frontend recognizes a test-to-code association. The three other original labels are preserved verbatim as edge kinds, not converted to `calls`. The original four labels are also repeated in notes. All edges are author declarations, not verified execution or causation.

Three flows retain ID, title and shared guard/report path. The public flow model has no per-step test link, scope, details or synthetic flag: these are preserved as explicit notes. Although this pinned schema still accepts the legacy `flow.tests` field, it is deliberately omitted because it cannot represent the original step-scoped association and the current frontend uses `tests` edges. Thus the shared global test edge can appear for all three flows even though only missing declares the step link. `omitted-link` is an intentional synthetic control. No test was executed and no coverage is claimed.

`inputs/shared-review-invalid-range.json` differs only in the guard node's `ref.lines`, changed from `[137, 139]` to `[999999, 999999]`, intended as an out-of-file reference control. All other JSON values match. This is the authored negative control; its observed CLI result and actual file length are recorded in README.md and evidence/final-run. Neither file asserts that schema, references, commit chain or diff validation passes. Validation may report legitimate additional findings; do not remove original facts merely to obtain a green result.

The preserved first draft was actually run by the coordinator; its raw outputs are kept outside this directory. The final pair only removes five `at` fields per file; the final pair was subsequently executed as recorded in README.md. This uses block-level nodes rather than the full declaration granularity recommended by the upstream authoring guidance. Even a green validation would not establish full compliance with that guidance.
