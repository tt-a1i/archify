# Goal：交付可离线探索的 Architecture Atlas v1

在 `tt-a1i/archify` 完成 Architecture Atlas v1：读者从总览节点进入独立内部图，继续深入，并准确返回原阅读位置；各层沿用现有 architecture IR、布局与探索能力，最终通过 `deliver atlas` 交付一个经过逐图和整包校验的离线 HTML。

这是实施任务。连续完成下述全部边界与验收，交付可运行功能、示例、测试和证据。分阶段实施不改变完成条件，计划、原型或仅完成编译阶段都不是终点。

本任务书自包含，是本次范围与验收的权威定义。若仓库有 `docs/nested-architecture-implementation-design.md`，将其作为实现论证参考；其中与本文冲突的草案内容以本文为准。该文件缺失时按本文继续。GitHub issue #262 第二条是需求背景，无需依赖其他对话还原任务。

## 1. 实施边界

### 必须交付

- 一个 atlas v1 清单包装多份本地 architecture schema v1 JSON；三层及更深的单父结构导航按相同规则工作。
- 每节点一个默认内部图，显式按钮与键盘可进入；普通点击继续 focus，缩放继续用于读图。
- 外部上下文引用、父层关系摘要、结构面包屑、按实际来路返回。
- 完整成员 HTML 内嵌，外层导航壳加一个活动 `srcdoc` Viewer 文档；离线启动、进入、返回、刷新深链及当前图导出。
- 统一地址、访问级历史快照、初始化与恢复、旧会话失效、加载失败恢复。
- 保留当前图内 search/focus/Passport、route/reach/lens、章节/故事、主题/预设、源码入口、现有导出与 Presentation Stage 的有效能力分支。
- 与旧单图输入、CLI、深链、校验和导出行为兼容；图集必需资源随现有技能打包流程可用，运行不增加 npm 安装或远程服务要求。

### 本次范围以外

其他四种图的图集成员、相关流程多入口、多父内部图、原地展开/语义缩放换层、跨图路径计算、自动接线、全局实体与属性同步、跨版本实体迁移、Atlas Delta、图集热预览、编辑器、后台生成或托管、移动端专项适配、原生 Fullscreen API、图包签名与来源认证。

首版接受完整成员模板重复。采用一个活动会话，不预先增加多个 iframe 缓存、运行时模板拼装、通用 provider 或消息总线。允许为既有渲染/Viewer 增加必要的内部接口；重构范围围绕本目标。

浏览器验收沿用现有 Chrome/Chromium 能力路径，至少一份实际版本同时验证 `file://` 和本地 HTTP。不新增 Safari/Firefox/移动端的完整支持承诺。Presentation Stage 指现有 CSS 演示模式，并由图集协调保留层级导航。

## 2. 固定的数据与 CLI 契约

清单使用 `atlas_version: 1`、`entry`、`meta`、`diagrams`、`details`、`references`。`meta.title` 必需；locale/preset 缺省沿用现有默认值。details/references 缺省为空数组，允许只有一个 entry 的图集。示例：

```json
{
  "atlas_version": 1,
  "entry": "system",
  "meta": { "title": "订单平台", "locale": "zh-CN", "visual_preset": "classic" },
  "diagrams": {
    "system": { "source": "system.architecture.json" },
    "payment": { "source": "payment.architecture.json" },
    "worker": { "source": "worker.architecture.json" },
    "orders": { "source": "orders.architecture.json" }
  },
  "details": [
    { "from": { "diagram": "system", "node": "payment" }, "to": "payment" },
    { "from": { "diagram": "payment", "node": "worker" }, "to": "worker" },
    { "from": { "diagram": "system", "node": "orders" }, "to": "orders" }
  ],
  "references": [
    { "occurrence": { "diagram": "payment", "node": "redis" }, "target": { "diagram": "system", "node": "redis" } },
    { "occurrence": { "diagram": "orders", "node": "redis" }, "target": { "diagram": "system", "node": "redis" } }
  ]
}
```

实现并文档化以下规则：

1. `source` 接受绝对本地 JSON 路径，或相对清单目录的本地路径；拒绝 URL/URI，允许合法 `..` 与符号链接。输出与任一输入的真实路径/文件别名不得相撞，提交前按既有输出保护规则复查。成员 `meta.output` 不决定交付位置。
2. entry 存在且无结构父节点；每个非根图恰好一个入向 detail，全部从 entry 可达。同一 from 唯一；拒绝自环、包含环、多父和孤立图。节点/图 ID 使用现有受限标识风格，地址采用 `(diagramId, localId)`。
3. reference 两端存在，occurrence 唯一，target 直达非引用定义节点且类型一致；拒绝自引用、引用链和引用节点拥有 detail。不同图相互引用各自的定义节点可以合法，不能误判为结构环。
4. 内部图是作者声明的模块结构范围，允许省略细节；外部对象以引用表示。校验器验证声明的格式与引用一致性，不声称核验真实架构归属。引用只标识同一对象，不传播连线、标签或布局。
5. 引用节点仍保留 database/backend 等类型，增加可见的外部上下文标记与限定引用元数据；标记进入 canonical SVG 并在最终检查前生成。来源对象由唯一入向 detail 推导，不另存 owner/subject。atlas 不扩展 architecture/common 的用户 IR 字段；detail/reference/父层上下文由 wrapper 推导，通过 renderer 内部参数传入。有效成员 IR 仍独立通过原 architecture schema，普通单图调用不传图集上下文。
6. 图集统一固定 UI locale/preset：子图缺省继承、显式冲突失败；运行时外观偏好由外层持有。标题、viewBox、章节、animation、engineering_profile 保留逐图语义。继承后的有效输入有可追溯摘要。
7. 逐成员延续 repository/sources 和工程画像验证。只提供一个现有语义的 `--repo-root`，不新增多仓库映射；成员的固定 revision 分别记录，不宣称整包来自同一提交。

新增公开命令仅为：

```sh
node archify/bin/archify.mjs deliver atlas project.atlas.json output.html --quality showcase --json
```

支持既有 deliver 的可选输出和 `--quality`、`--json`、`--repo-root`、`--open` 语义；默认输出为清单旁的 `<清单文件名去末尾扩展名>.html`。atlas 清单不另加 output 字段。拒绝未知选项和多余位置参数。`--open` 只在成功原子提交后按既有规则运行，自动验收保持关闭。现有 `visual-check <output.html>` 必须识别并检查 atlas 产物，这是原命令适配新产物；无需为 render/validate/preview/compare/migrate 增加 atlas 分支。整包确定性检查可以由内部模块和测试调用。

## 3. 构建、会话与状态边界

### 构建

冻结清单及所有成员的读取字节，后续只使用冻结数据；继承配置并生成图集上下文，逐图执行 schema、布局、源码/工程画像和产物检查，再装配、检查整包，最后同文件系统原子提交。逐文件读取不等于活跃仓库的事务快照。

启动 gate/bridge、静态引用标记和 atlas 的离线资源处理都在成员最终检查前生成。完整成员字符串作为安全转义的未执行 JSON 数据打包；运行时原样设置 srcdoc，仅通过 init 传动态状态。浏览器清单只使用图 ID、关系和已编译内容，构建机的绝对源路径与暂存位置留在 CLI 侧。整包检查解析实际交付 HTML，验证所有成员的字节与逐图回执，不能只检查外壳或相信打包前结果。保留成员 `single_svg` 门禁；摘要证明字节一致性，不承担签名或来源认证。

图集启动、导航和导出不发起自主网络请求：移除 atlas 成员的远程字体 link/preconnect 等加载入口，使用既有本地字体回退，资源本地内嵌。普通单图的字体行为不在本次改动范围。网络断言排除初始本地 HTTP 页面导航和用户明确点击源码链接；允许 srcdoc/data/blob，不只统计请求成功数。

回执保留清单、原始源、有效输入、逐图产物和最终产物的 SHA-256/字节数及各图检查结果。`--json` 成功/失败均输出一个结构化结果；失败包含阶段、稳定 code、图 ID/清单位置等适用定位信息。任一失败保留旧产物并清理暂存，不增加独立 sidecar 联合提交机制。

### 会话与导航

采用 atlas 会话模式，不复用会隐藏工具的 embed 模式。外层拥有地址/历史/结构导航/全局外观，内层拥有当前图的读取与导出。通用启动入口覆盖模板头部偏好初始化与主体 Viewer；独立图仍直接启动。

首次 bridge-ready 仅按当前新 iframe 窗口和启动阶段接收；init 分配会话代号。后续消息绑定 `sessionId`、`entryId` 和导航事务。`load` 不代表 Viewer ready：先初始化、等待布局稳定、恢复语义状态，再恢复相机；期间抑制自动取景、播放与地址回写。

顶层是唯一 history 写入者，成员统一经过地址接口读取/报告局部状态，生成外层分享链接。地址如 `#diagram=worker&focus=executor`，延续图内有效的 view/route/relation/reach/lens 组合。跨图进入 push，图内变化合并当前条目；查询参数中的主题/预设/演示状态也不能被覆盖。

按每次访问保存逻辑相机/缩放、必要滚动、选择、章节和已提交阅读状态；悬停、弹层开合、DOM 引用、动画进度不保存。恢复后动画停止。结构面包屑反映 detail 树，返回按钮反映实际访问记录；冷启动无来路时提供返回总览。

相机的稳定变更合并到当前访问快照。popstate 在任何 await 前取消旧会话写入资格；仅 entryId 与当前 history 条目匹配的活动会话能更新快照。迟到消息不得污染目标记录。未提交的内部导航失败可恢复来源；Back/Forward/冷启动失败应保留目标地址展示错误及重试/返回入口。

父层摘要只来自宿主节点的作者入出边；有作者关系 ID 才支持关系定位，无 ID 只显示。detail/reference/摘要不生成通信边属性，不参与图内 BFS，也不猜内部落点。

### 既有能力与导出

SVG/PNG 必须实际成功导出当前层完整规范图，含外部上下文标记、无临时相机/面板；JPEG/WebP、Share Card、route/reach Share Card 和 WebM 沿用既有能力条件，分别有成功分支证据。WebM 在至少一个支持独立图录制的真实浏览器验证有效文件。源码链接保持对应成员的已验证证据。

复制能力可因真实 API/权限限制采用明确下载或手动复制降级；不能把新 iframe 策略造成的失败当成浏览器不支持。同浏览器同条件下独立 Viewer 可用而 atlas 不可用的功能，按回归处理。Presentation Stage 由外层协调且保留层级导航，不新增原生 Fullscreen API。

异步导出/录制期间，显式内部导航暂缓或允许取消；浏览器 Back 取消旧会话任务并忽略迟到结果。任何情况下都不能把新图内容交给旧导出请求。

## 4. 验收矩阵

准备四张有效基准图：system→payment→worker 构成三层，system→orders 是另一分支；payment 与 orders 共享 system/redis，并各有同名 controller。含有作者 ID 和无 ID 的父关系、中文/转义文本、一份合法源码证据、可录制 trace、图内可达与不可达案例。另准备通过现有质量规则的 30 节点总览与 20 节点子图。节点数与三层是验收样例，不是硬编码产品上限。

D＝实际 CLI/文件或纯逻辑断言；B＝真实浏览器行为；V＝对实际产物截图/导出图像的视觉检查。模拟 DOM 和“按钮存在”不能替代 B/V。

| ID | 操作/输入 | 必须观察到的结果 | 证据 |
|---|---|---|---|
| AC01 | 合法单图/四图；逐项破坏版本、类型、根、detail、reference、配置、参数 | 合法项成功；未知图/节点、环、多父、孤立、重复 from/occurrence、引用链、类型/配置冲突和非法 CLI 失败且定位准确；合法互引定义通过 | D |
| AC02 | 含中文、`</script>` 与特殊字符；解包并改变隐藏成员字节 | 解包字节与逐图回执一致、成员重新通过门禁、文本不执行；字节与回执不一致、缺成员、错误摘要或改动后违反成员/整包门禁均被拒绝，不要求识别一份全部合法重建的新图包为伪造 | D+B |
| AC03 | 已有可信产物；坏子图/引用、输出与清单/成员同路径或别名、提交前换向链接 | 非零退出；旧产物与全部输入字节不变；暂存清理且不调用 opener；成功才允许既有 open 行为 | D |
| AC04 | 输入冻结后改写源文件；含继承配置与源码证据 | 交付仍对应冻结字节与有效输入；每图证据/revision 归属准确；不把源摘要冒充完整渲染输入摘要 | D |
| AC05 | 三层进入返回；两来源访问共享 Redis；同名节点；有效/无效深链冷启动与刷新 | 目标/焦点准确；面包屑表示结构，返回表示来路；引用保持 database 身份；无效地址显式错误且可恢复 | B |
| AC06 | 同一 viewport 的非默认、非边缘相机与有效语义状态，进入后返回 | 布局稳定后锚点偏差≤2 CSS px、缩放相对误差≤0.1%、滚动偏差≤2 px；语义 ID 精确恢复、动画停止。窗口改变时恢复有效逻辑范围，不要求像素相同 | B |
| AC07 | 连续切换、20 轮往返、Back 与旧 ready/state/snapshot 交错、目标加载失败 | 活动 Viewer≤1；只有当前会话/访问/事务能提交；目标快照不被污染；地址、画面或错误目标一致；无 iframe 自身导航产生的额外 Back 停靠点 | B |
| AC08 | 当前图路径/上下游/角色/章节；父摘要及引用；HTTP 与 webhook 不同关系 | 同图结果准确、diagram/主题等地址不丢失；只查当前作者通信边，不跨层拼接、不把双向关系说成请求响应 | D+B |
| AC09 | 最终同一 HTML 在 file 和本地 HTTP 冷启动、刷新、深入、返回及导出；监测请求尝试 | 无自主网络请求、无运行时源 JSON 读取；中文与回退字体可读；用户主动源码跳转单独记录 | B |
| AC10 | 当前图 SVG/PNG、其他既有导出、共享节点标记与临时浮层 | 静态图是当前完整范围、标记保留、类型不变、浮层不泄漏；输出文件可解码；route/reach 卡片与当前事实一致 | D+B+V |
| AC11 | trace 图录制；复制支持/受限分支；导出时导航/Back；演示模式 | 有效 WebM；复制成功或明确可用降级；取消/延迟结果不串图；演示保留导航；不通过隐藏既有功能规避回归 | D+B |
| AC12 | 30/20 节点样例的实际外层＋活动成员，覆盖现有四个 desktop viewport 和端点明暗主题 | 沿用现有可读性常量与几何门禁，检查外壳及成员；节点可读且可到达、默认视图无溢出/遮挡；不用裁剪或缩小字号骗过检查 | B+V |
| AC13 | 原有五类单图、旧深链/模板工具、CLI/导出与打包运行 | 相关回归及仓库要求检查通过；打包环境无 node_modules 仍能 deliver atlas；所需 schema/运行时资产未遗漏 | D+B |
| AC14 | 逐项移除本次新增的可疑抽象或 UI，重跑受影响验收 | 通过则保留删除，不通过则恢复；记录候选、结论及重跑证据，不以代码行数判定简化成功 | D/B/V |

至少一个实际 Chrome/Chromium 版本完成 B；记录版本、平台、协议与条件。扩展现有 `archify/bin/visual-check.mjs` 识别 atlas，复用既有 viewport/测量/回执语义，检查实际外壳与所有成员，不能只测外壳空页面。回执绑定最终 HTML 的 SHA-256/字节数并标识被检查图。自动 browser_evidence 与人工/图像 visual_review 分开报告，失败或跳过不标成通过。

不凭空设定图集字节数、最大层数或毫秒级性能承诺；记录代表样例的字节数与切换观察。资源失败给诊断，不能降级成缺图的成功交付。

## 5. 执行与完成

1. 读取适用 AGENTS、现有交付/Viewer 契约、CLI/模板/渲染与测试入口；记录基线及工作区已有改动。确认当前代码可复用的检查与必须新增的连接点。
2. 分阶段连续实现：清单与整包编译；单活动会话与地址历史；上下文/既有能力/离线资源；文档、示例、打包与最终证据。独立子任务可并行，先收敛共同数据和会话契约。
3. 用真实失败样例驱动必要测试，完成矩阵及仓库要求的检查。用户输入文本不得当作 HTML/脚本执行；所有成员都参与验收。
4. 完成 AC14 消融后，重新交付最终样例并收集与最终字节对应的证据。不要把失败交付后残留的旧 HTML 当成本次结果。

实施可修改本地代码、schema/生成校验器、模板、测试、示例、文档与打包清单。常规实现选择自行解决；不把每阶段结束当成必须再次确认的节点。发布版本、推送、合并、部署和对外评论不在本目标内。

在 macOS，优先内置 `@Browser`。若真实自动验收需要启动 Chrome/Chromium、Playwright/Electron 或其他 GUI 进程，按正常审批路径在 Codex sandbox 外运行。若不可用或被拒，停止该启动尝试，给出准确的手动 Terminal 命令并继续不受影响的工作；不在 sandbox 内重试失败 GUI 启动。

完成时交付：

- 实际可用的命令、代码与示例路径；至少一份四图三层且含共享引用的离线 HTML。
- 清单/成员/整包回执、最终产物摘要，以及可复查的导出文件和浏览器/视觉证据。
