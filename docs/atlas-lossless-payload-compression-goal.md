# Goal：在功能与视觉完全保真的前提下压缩 Architecture Atlas

为 Archify 的 Architecture Atlas 增加可逆的 payload 压缩封装，将固定 Maka 五图样本从 1,421,122 字节压缩到不超过 525,000 字节，同时保持当前分支生成的图形、字体、样式、动效、交互、导航、详情、开发指南、源码证据、分享、导出、离线能力和 CLI 校验能力不变。

本文件是可直接交给 Codex 执行的独立 goal。执行时完成实现、测试、消融、全新生成的 Maka 与 OpenPI 产物及真实浏览器验收。编写本文件不等于启动实施。

## 1. 固定方案

保留当前 `bundle_version: 2` 的资源去重、成员分块和按访问还原规则。先按现有生成链路产生并完整校验规范 v2 payload，再只对 `archify-atlas-data` 的序列化字节执行确定性 gzip 压缩，以 Base64 有界分块写入同一个 HTML。

新 HTML 使用独立、版本化的压缩 envelope，至少包含：

- envelope 版本；
- codec；
- 未压缩 UTF-8 字节数；
- 未压缩 payload 的 SHA-256；
- 有序 Base64 字符串块。

浏览器解压后把逐字节一致的 v2 payload 交给现有 `readAtlasBundle` 和 Atlas Runtime。Node CLI 解压后继续使用现有 `unpackAtlas`、`checkAtlas` 和成员回执校验。压缩 envelope 是交付编码，不改变 Atlas manifest、architecture schema、成员 HTML、公开 URL 或 Viewer 状态模型。

raw-v2 只作为兼容输入与受控对照，不增加面向用户的“关闭压缩”选项。测试可通过内部 renderer/fixture 取得同次编译的 raw-v2 payload；正式 `deliver atlas` 继续只有一个默认输出路径。

浏览器优先使用原生流式解压能力，并包含一个随 HTML 内嵌、无需联网的 gzip fallback。两条路径必须还原相同字节并通过相同功能测试。fallback 使用经过验证且许可证兼容的实现，随发布包保留必要归属；不手写未经充分验证的 DEFLATE 算法，也不把外部 CDN、运行时安装或网络请求变成打开条件。

不采用“解压后 `document.write` 替换整个 HTML”的完整页面自解压方案。Atlas 外壳、主题初始化、错误容器和浏览器地址保持现有生命周期，只把启动 Atlas Runtime 的时机推迟到 payload 解压与解析成功之后。

## 3. 实施边界

### 本轮包含

- Atlas payload 压缩 envelope、确定性编码、Base64 有界分块和错误诊断。
- Node 原生 gzip 编解码；浏览器原生解压与离线 fallback。
- 浏览器启动门控：解压、长度检查、解析成功后才启动现有 Atlas Runtime。
- CLI、交付回执、visual-check、示例、文档、测试和 `archify.zip` 的必要更新。
- 旧 raw v1、raw v2 与新 compressed-v2 的读取兼容；新交付默认使用 compressed-v2。
- 与当前无闪烁切层、节点开发指南、关系/源码操作及紧凑交付相关的回归修复，仅限压缩改动暴露的问题。

### 本轮不包含

- 改写图内容、布局、配色、字体、图标、阴影、间距、响应式规则或任何 Viewer UI。
- 删除或缩短节点、关系、卡片、来源、回执、开发指南和 Atlas 元数据来满足预算。
- 降低图片或视频导出尺寸、质量、帧率、时长或格式范围。
- 改变切层、预加载、候选提交、历史、深链、主题、演示、路径、地图、透镜或详情面板状态模型。
- 压缩普通单图 HTML、引入 Web Worker、CDN、多文件部署、服务端解压、远程字体或运行时依赖下载。
- 用完整 HTML 自解压替换文档、用 `eval`/`new Function` 执行解压内容，或在压缩失败后显示旧成员冒充成功。
- 修改 Codex 桌面端本身、提交、推送、合并、发布或部署。

## 4. 功能和视觉保全规则

“功能不减少”以实施前当前分支的真实产物为基线，不以本 goal 列出的项目作为白名单。执行者必须从 DOM、菜单、快捷键、公开地址参数、导出入口和现有测试生成一份功能清单；最终逐项对照。任何现有能力缺失都优先判定为失败，即使体积预算已经达到。

压缩前后的规范 v2 payload 必须 UTF-8 字节完全相同。由它还原出的每个成员 HTML、内联 CSS、离线字体、脚本、SVG、节点数据、来源数据、开发指南数据及回执必须逐字节相同。不得先删功能或改样式，再把修改后的结果称为“无损压缩”。

视觉保真至少覆盖：

- 浅色与深色；当前全部视觉预设；正常、hover、focus-visible、选中、dimmed、route、reach、lens、搜索、演示和开发指南状态；
- 总图、子图、孙图、窄屏、常规桌面和宽屏；
- 字体、字号、字重、行高、颜色、边框、圆角、阴影、图标、网格、节点与连线布局、详情排版；
- 路径动画、故事播放、切层过渡、减少动效偏好，以及导出时的规范静态状态。

静态状态在同一浏览器、视口、主题和关闭动效条件下做基线/候选截图对照。动态效果比较动画名称、时长、缓动、关键状态、开始/停止行为和代表帧，不用随机采样时刻的像素差替代行为检查。任何视觉差异必须证明来自非确定性渲染或环境；压缩实现不得改变成员资源或计算样式。

## 5. 格式和错误约定

| 项目 | 要求 |
| --- | --- |
| 编码范围 | 只压缩安全序列化后的 `archify-atlas-data` payload。Atlas 外壳和 Runtime 保持普通 HTML/JS，便于启动和错误显示。 |
| 确定性 | 固定 gzip 参数、资源顺序、JSON 序列化和分块规则；同输入、同生成器版本重复输出字节一致。 |
| 分块 | 按最终 HTML 中每行 UTF-8 字节计算；Base64 数据行不超过 8,192 字节，不生成新的巨型单行。 |
| 原生路径 | 异步解压完成后才解析并启动 Runtime；解压期间保持正确主题背景，不出现白屏闪烁或可交互的半初始化页面。 |
| fallback | 在原生 API 不存在或被测试显式禁用时离线工作；功能、样式、错误处理和输出与原生路径一致。 |
| CLI | 同一入口接受 raw v1、raw v2、compressed-v2；解压后沿用已有结构、回执、来源、关系和成员检查。 |
| 完整性 | Node 始终校验 envelope 类型、版本、codec、分块、Base64、未压缩字节数和 SHA-256。浏览器始终校验 gzip/CRC 和字节数，在 Web Crypto 可用时再校验 SHA-256；缺少 Web Crypto 本身不得让原本可用的浏览器失去打开能力。成员回执继续描述还原后的原始成员 HTML。 |
| 错误 | 截断、篡改、错误 codec、非法 Base64、解压失败、长度或摘要不符都失败关闭。CLI 不覆盖旧产物；浏览器显示可访问、可本地化、可重试的错误。 |
| 安全 | 解压结果只作为 JSON 数据解析，沿用现有 script JSON 转义；不执行数据字符串，不增加远程请求。 |

## 8. 性能与宿主观察

压缩的目标是减少物理 HTML 文件对 Codex 文件面板和其他宿主的读取、传输、索引与高亮压力。浏览器会增加一次解压步骤，因此分别记录 raw-v2 和 compressed-v2 在同一设备、浏览器、协议下的导航到 Atlas ready 时间、解压时间和可获得的长任务。

固定 Maka 在正常原生路径不应出现归因于解压的 50 ms 以上主线程长任务；若环境测量不稳定，报告至少五次冷/热样本的中位数和范围，不用单次最好成绩。fallback 路径以功能兼容为首要条件，同时记录其耗时，不通过隐藏 loading、提前宣告 ready 或推迟错误来改善数字。

Codex 桌面端卡顿是独立宿主现象。工具允许时，用同一面板和打开方式对 raw-v2/compressed-v2 各测至少五次；无法取得宿主数据时如实标记未测，不用 Node 或 Chrome 时间声称 Codex 卡顿已经修复。宿主观察缺失不降低 AC01–AC14 的实现要求。

## 10. 规格消融记录

本节是 goal 设计的消融，不替代实施后的 AC13。

- **保留 payload-only。** 完整 HTML 自解压原型约 421,600 字节，只比 payload-only 多省约 64 KB，却需要替换整个文档并扩大地址、加载事件和脚本执行风险；从实施方案中删除完整页面封装。
- **保留 fallback。** 仅依赖原生 `DecompressionStream` 会把该 API 变成新的打开前提，不能满足严格的功能保全；恢复离线内嵌 fallback，并以 525,000 字节预算覆盖其体积。
- **删除额外字符串去重。** 当前 Maka 成员片段的精确重复只剩约 95 字节，新增通用字典不能用收益证明复杂度；本轮不实现。
- **删除 JSON 空白优化。** 完全紧凑序列化只节省约 2.2 KB，并产生约 1.32 MB 单行；一空格缩进只节省约 945 字节。两者均不作为主方案。
- **保留现有 v2 去重和分块。** gzip 是 v2 之上的可逆交付层，不替换公共资源去重、成员按需还原和有界行规则；移除这些能力会扩大解压工作集或重新产生巨型源代码行。
- **保留完整功能基线与视觉对照。** 单靠字节往返不能发现启动门控、主题首帧、fallback 或导出回归，因此保留真实浏览器、动态效果和功能清单验收。
