# Goal：让 Architecture Atlas 切层保持画面与阅读状态连续

在 Archify 当前分支实现常驻工作台与就绪后提交的图层切换。用户从目录、节点下探、面包屑、跨图引用或返回入口切层时，目录和全局控件保持稳定；目标图完成主题、字体、布局及阅读状态恢复后才显示。以无切换动画为默认实现，消除旧页提前消失、新页初始化过程外露造成的闪烁。

这是实施 goal。完成代码、必要测试、示例交付和真实浏览器过程验收；仅提交方案、通过 Node 模拟测试或得到两张静态截图不算完成。本文是本轮范围与验收的权威定义，不需要从聊天记录恢复需求。适用的工具权限、安全限制和 AGENTS.md 仍须遵守。

## 1. 范围与兼容边界

### 本轮交付

- 常驻图集工作台：品牌、目录容器、目录搜索及全局工具栏。概览、详情、关系、源码内容继续随当前图和所选节点更新，保留现有完整能力和入口。
- 跨图导航的准备、提交、取消、失败及历史恢复流程；目录点击、节点下探、面包屑、规范定义引用、应用返回按钮、浏览器前进/后退均覆盖。
- 正确主题的首次打开、有效/无效深链、刷新、局部延迟反馈、键盘焦点与读屏行为。
- 现有单文件离线 Atlas 交付及当前图导出；保留普通单图 Viewer 行为、清单/成员 schema、公开 CLI、地址格式和来源检查。
- 延续刚完成的宽图布局：桌面固定 280px 左栏，先预留工作区再适配和居中；节点选择和检查器变化不改变画布。既有非宽图、紧凑、嵌入、演示和打印行为保持。

### 本轮不扩展

不增加整页渐隐、滑动、节点变形或镜头钻入；不增加全部成员预加载、常驻多图缓存、缓存淘汰框架、跨图搜索、跨会话阅读数据库、通用消息总线或图集编辑器。不重新设计图形语义、连线布局和详情样式，不借本轮升级依赖或发布产品。

沿用现有 architecture 成员和浏览器支持范围，不承诺所有浏览器/设备或任意图包规模的切换耗时。300ms 仅是加载反馈的显示规则，不是切换完成的性能承诺。

### 对既有设计的明确调整

`docs/nested-architecture-goal.md` 中“一个活动会话”的语义保留。本轮允许短暂同时挂载当前 Viewer 与一个候选 Viewer，以便保留旧画面并准备目标；最多一个 Viewer 能接收阅读操作或执行导出。候选提交/取消/失败后立即清理不再需要的实例，稳态只留当前 Viewer。这不是已访问成员缓存。

旧工作台文档中按访问恢复目录查询、以及根据图形宽度决定侧栏的描述，以本文的共享目录状态和当前工作区布局为准。实现围绕现有模块建立必要接口，避免复制节点、关系或来源的第二套数据模型。

## 2. 用户状态的归属

| 状态 | 归属与恢复规则 |
| --- | --- |
| 主题、视觉预设及现有全局外观偏好 | 图集级共享；准备期间改变偏好，候选必须使用最新值提交 |
| 目录打开状态、搜索词、列表滚动、搜索光标/选区 | 当前图集会话共享；换层及 Back/Forward 不重置，不恢复成某次访问的旧目录状态 |
| 目录键盘操作位置与焦点 | 常驻控件保持 DOM 身份；遵循用户真实点击/键盘操作，不因重建丢焦点或抢到标题；已有中文输入组合不被无关切层初始化打断 |
| 镜头、节点/关系选择、章节、route/reach/lens 等图内状态 | 沿用访问级快照与现有地址语义；Back/Forward 恢复离开该次访问时的状态 |
| 详情/关系/源码页签、概览与面板滚动、父层披露 | 按访问保存；返回恢复，内容始终来自对应图层及选择 |
| 当前图、标题、面包屑、目录当前项、检查器数据、导出目标 | 同一提交结果；候选准备阶段只显示“待打开”的反馈，不提前冒充当前图 |

目录进入一个新访问时采用目标的正常初始阅读状态；显式 focus/relation 等导航参数照常应用。目录共享状态不等于跨会话保存，也不需要持久化所有成员的运行实例。

访问快照只恢复成员内的阅读和焦点状态，不覆盖常驻工作台状态，也不把焦点从用户正在操作的目录/工具栏抢走。旧快照中的目录字段不参与访问恢复；历史条目里的旧外观偏好不能覆盖工作台的当前偏好。

“当前图”仅指已提交、仍有活动权限且访问身份与当前地址一致的图。同图目录项点击是 no-op：不收起目录、不清空搜索、不重建 Viewer、不增加历史。在显式导航准备或导出等待期间，再点该当前图表示取消待切换。原生历史导航中暂留的旧图已无活动权限，点击其目录项应发起新的显式导航，成功后才建立新访问，不能直接恢复旧会话权限。当前图内不同 focus/relation 按既有图内地址更新处理，不走跨图重建。

## 3. 切换与提交规则

### 显式导航

1. 点击立即提供原有按压/键盘反馈，记录最新有效导航意图。准备期间旧图持续可见并可继续阅读、缩放和选择，保留其原有播放行为；目录始终可操作。
2. 在不可见但能完成真实布局的区域准备唯一候选，使用提交后实际可用的工作区尺寸，包含侧栏、工具栏和目标章节等占位。候选不得进入 Tab 顺序或可访问树，不响应用户快捷键，不自动播放、录制、下载或回写当前地址。不要用 `display:none` 的零尺寸结果当作就绪布局。
3. 候选就绪需要主题/预设、字体、导航上下文、语义状态、工作区及工具栏布局、目标相机和滚动恢复完成。复用现有稳定布局契约；单独的 iframe load 或 bridge-ready 不构成提交条件。
4. 就绪前如果主题、尺寸或导航意图变化，以最新条件重新确认就绪。过期候选的消息和定时器不得提交或回写状态。
5. 提交前同步捕获当前访问的最终阅读状态，再将目标画布、标题、面包屑、目录当前项、概览/检查器和地址提交为同一可见结果。旧 Viewer 的操作和写入权限先失效，随后释放；候选成为唯一活动 Viewer。显式导航此时才增加历史项。
6. 目录触发的导航保留目录操作焦点。从即将移除的图内按钮触发下探时，提交后将焦点放到目标图可见标题或明确入口；返回时恢复原触发位置，元素不存在才使用稳定回退。

初始化 session 与活动权限须区分。候选允许初始化并报告 ready/error，但提交前的 `ArchifyAddress.active` 或等效活动资格必须为 false，不能导出或提交地址/访问快照。父壳按候选窗口、访问身份和事务接收候选就绪消息，不要求其 entry 已成为当前 history entry；地址和访问快照写入仍只接受已提交且匹配当前历史项的活动会话。

### 延迟、失败和连续操作

- 目标在 300ms 内完成时不显示加载提示；仍在准备时，300ms 后在目标目录项或标题附近显示简短状态。只需一个局部反馈，成功、取消和失败时清理；不使用整页遮罩、骨架或假进度。
- 连续 B→C→D 请求以最后一个有效目标为准。先销毁被替代候选，再准备下一个；未显示的中间目标不增加显式导航历史。再次请求同一待打开目标应合并，不重启计时与准备。
- 显式导航失败/超时：旧图及其地址、当前项、阅读状态保持，恢复其正常操作；局部给出目标名称、失败原因、重试和继续选图的入口。沿用现有启动超时边界。无旧图的首次打开失败使用正确主题的可操作错误界面。
- 全局外观或窗口尺寸在准备中变化，旧图按现有规则响应；目标在最新尺寸、主题下完成布局才可提交。

### 浏览器历史与深链

应用 Back 按浏览器历史遍历，快照按访问身份恢复；顶层仍是地址/历史唯一写入者。分享链接和有效冷深链保持原格式。

原生 Back/Forward 或外部 hash 改动发生时，浏览器可能已经改变地址。立即停止旧访问的写入和录制权限，旧画面可以暂留为不可交互的视觉内容。候选成功后恢复地址所对应的访问，不重复 push 历史；过期请求不能回写已离开的 entry。

若这种导航失败，保留目标地址并在右侧工作区明确显示目标错误、重试和返回/选图入口；不得悄悄用 `replaceState` 把该历史项改写成旧图。若保留旧图预览，必须明确标注其身份，保持不可交互，禁止将其当作目标图分享/导出。常驻目录仍可继续导航。无效深链同样给出明确错误，不静默清掉参数或展示其他图冒充成功。

### 导出与资源生命周期

- 已有导出/录制进行中时，显式导航按既有规则等待结束，多个请求只留最后一个；等待提示使用“导出完成后进入…”，此时不启动候选。
- 切层准备期间暂不接受新的导出/录制，给出简短原因；提交或显式导航失败恢复正常。所有可用导出均只针对已提交的当前成员。
- 原生历史离开按既有规则取消录制、释放 tracks，阻止迟到的自动下载。候选取消、超时和失败同样释放监听、计时器及其他资源；稳态无隐藏 Viewer、重复快捷键处理器或失效会话写入。
- 工作台控件通过当前 Viewer 的既有能力接口工作，不复制一个只覆盖 PNG 等少数格式的替代导出菜单。

## 4. 验收标准

下列项目全部是实施后的完成条件；本文中的方案推演不是通过证据。

| 编号 | 必须通过的验收 |
| --- | --- |
| AC01 画面连续 | 总图→子图→孙图→返回，在浅/深色及禁用全部动效时，准备期间保留旧画面；无整页空白、错误主题帧或目标先显示后重新取景/跳位。标题、目录当前项和画布仅在提交时同步更新；历史失败按上述明确例外展示错误。 |
| AC02 工作台稳定 | 切换前后常驻品牌、目录搜索、全局工具栏的 DOM 身份不变；不改变窗口/模式时外壳边界误差≤1 CSS px。有搜索词、选区和目录滚动时换层/返回保持状态；显式焦点操作按用户意图执行。 |
| AC03 阅读恢复 | 在非默认缩放和平移下选择节点/关系，打开源码或关系页签并滚动；下探后通过应用 Back 和原生 Back/Forward 返回，恢复该次访问状态和可用触发焦点。镜头逻辑数值/像素误差按现有测试容差，不能以重置取景替代恢复。 |
| AC04 延迟反馈 | 可控就绪时钟验证 300ms 前不出现加载提示，仍未就绪时在阈值后显示局部提示。真实浏览器另验证延迟约 1s 时旧图一直可见、目录能改选；成功、取消、失败均清除提示，无布局挤压。 |
| AC05 竞争与取消 | 受控延迟使 B 比 C/D 更晚就绪，快速请求 B→C→D，只能提交 D。重复请求待打开目标不重建；点击仍有权限的当前图取消显式准备。原生 Back 尚未 ready 时点击暂留旧图，走新的显式导航，旧会话不得复活。迟到 ready/error/snapshot 不改变画面、URL、历史或提示。 |
| AC06 历史一致 | 显式准备/失败/取消不产生已访问项，成功产生一个；当前图 no-op 不产生历史。三层路径的 Back/Forward、连续历史遍历、历史准备中转为显式选图、有效/无效冷深链、刷新和 hash 变化无重复项或跳转循环，错误处理不篡改其他访问。 |
| AC07 失败恢复 | 分别注入初始化异常和超时。显式失败保留旧图可读与正确地址；历史失败展示目标错误而非冒充旧图。重试和另选目标均能继续；首次加载失败有正确主题和可操作入口。 |
| AC08 主题与尺寸 | 初次打开、切换准备中改变主题/预设及 resize，最终内容采用最新设置，无主题翻转和首帧错误尺寸。桌面延续工作区居中及页面容纳门禁；窄屏按原规则流式布局，不覆盖图与控件。 |
| AC09 焦点与无障碍 | 目录鼠标/键盘导航、搜索输入、Tab 和返回可用。候选不出现在可访问树或 Tab 顺序；屏幕阅读器能获得适量局部状态通知。系统减少动态效果下仍满足 AC01。 |
| AC10 单活动与清理 | 准备阶段最多当前+候选两个渲染实例，候选无操作/地址/导出权限；取消/失败/成功后无多余实例。连续至少20次切层后活动监听/计时器/录制资源回到稳定基线；不把正常历史快照增长误判成运行实例泄漏。 |
| AC11 原有能力 | 保留详情、关系、源码、目录、章节、route/reach/lens、图内搜索、演示及当前图导出。覆盖导出忙时排队/取最后请求、准备时禁新导出、原生历史中止录制；运行既有 Atlas 导航、布局、地址、导出及普通单图相关回归。 |
| AC12 交付真实性 | 使用当前分支实际源码重新生成至少四图、三层并含共享引用的代表图集；新示例含不同宽高比及章节/概览差异。最终 HTML、源规格、生成入口/代码摘要和所有检查回执路径一致，逐成员及整包校验通过，保持离线启动和自主网络请求为零的既有约定。 |
| AC13 实际过程证据 | 在真实浏览器记录切换过程，而非只截前后两张图。覆盖浅/深色、快/慢/失败/乱序/返回/resize，保留视频或连续帧、提交时间及逐帧可见图身份和边界测量；实际查看代表片段。不能用 DOM mock、无异常、iframe load 或布局稳定回调替代无闪烁的视觉验收。 |
| AC14 消融 | 功能稳定后逐一移除可能多余的抽象/状态/反馈组件，重跑原验收；通过则保留删除，失败则恢复。关闭所有动效时重跑 AC01–AC09；记录尝试、结果、证据路径及最终取舍。 |

浏览器范围：遵循现有 Chrome/Chromium 验收能力，桌面覆盖 1440×900、1600×1000、1920×1080、2048×1320；补目录布局断点两侧和至少一个窄屏尺寸。先用代表三层路径覆盖这些尺寸/主题，再在一个主桌面尺寸集中运行慢就绪、失败及竞争场景；不要求每种故障做无意义的全排列。至少验证同一交付物的 `file://` 与本地 HTTP，前提是当前工具策略允许。

“无闪烁”只对记录的浏览器、尺寸与场景作证。视频/截图采样可能漏帧，需结合逐帧 DOM 状态及提交时序判断；标明证据局限，不宣称覆盖所有设备或无限规模。

方案消融已排除整页动效、常驻多图缓存和全屏骨架：AC01/AC03 分别由就绪提交和访问快照承担，慢加载由 AC04 的局部提示承担。初稿中的“准备前强制暂停旧图播放”也已删除；保留旧图原行为并禁止候选播放即可满足连续显示和单活动边界，避免引入取消后恢复播放的新机制。局部延迟提示仍保留，否则不能满足 AC04。这是规格覆盖推演，不是实现测试结果；实施后仍须执行 AC14。

## 5. 执行与交付

1. 确认实际分支、HEAD 与已有工作区改动。当前开发上下文为 `codex/architecture-atlas-v1`；以执行环境实际状态为准，不覆盖已有改动或擅自切到发布版/已安装旧 Skill。读取相关 AGENTS、当前交付契约及以下入口。
2. 在真实导航调用边界建立能复现“旧 ready 画面先被移除，目标尚未 ready”的失败测试，并补竞争/历史/资源约束；在修改前记录基线。现有离线诊断只解释运行时顺序，不是浏览器白帧证据。
3. 明确工作台共享状态与访问快照的唯一归属，实施常驻外壳、候选准备和一次提交。分阶段实现可并行，但最终须按统一会话/历史契约接通，不以阶段完成为终点。
4. 按仓库当前脚本生成受影响模板、示例与必需打包产物，运行必要测试和 AC 矩阵。验收钩子仅用于测试；用户页面中不加入调试状态、构建机路径、虚构进度或技术检查清单。
5. 完成 AC14 后重新交付最终样例，对最终字节收集确定性、浏览器和感知证据。交付失败后保留的旧 HTML 不得冒充新结果；记录实际 output 路径和哈希，核对成员内嵌运行时代码与当前源码一致。

相关入口：

- `archify/renderers/shared/atlas-shell.mjs`：会话、历史、载入与导出协调。
- `archify/renderers/shared/atlas-navigation.mjs`：工作台内容、目录与检查器状态。
