# Atlas HTML 体积调查（2026-09-12）

当前 OpenPI 图集存在可无损消除的重复打包。对这份 5 层图集，公共脚本、样式和字体只存一份，再把长字符串分块，预计从 4.48 MB 降到约 1.36 MB，减少约 70%。这是隔离的打包实验，尚未接入生产生成器，也没有据此宣称 Codex 桌面端卡顿已经修复。

以上都是原始成员 HTML 的字节数；外层 JSON 的转义还会增加体积。图集并未同时启动 5 个 Viewer：现有运行时只保留当前页面与切换中的候选页面。存储重复与同时运行是不同问题。

`atlas-delivery.mjs` 逐成员生成完整 HTML，`atlas-shell.mjs` 把整个 bundle 序列化进一个 JSON script；切换时通过 `frame.srcdoc = bundle.members[diagram].html` 启动目标页面。这解释了图集为何随层数重复增加 Viewer 体积。

## 无损实验

| 方案 | 估算完整文件字节数 | 成员逐字节还原 |
| --- | ---: | --- |
| 当前文件 | 4,475,495 | 基准 |
| 仅共享脚本 | 2,494,422 | 5/5 一致 |
| 共享脚本、样式和字体 | 1,339,766 | 5/5 一致 |
| 再共享重复 JSON 数据 | 1,225,498 | 5/5 一致 |
| 共享脚本、样式和字体，并限制字符串分块长度 | 1,358,804 | 5/5 一致 |

估算包括现有外壳、完整元数据及最小还原函数，不包括未来生产格式的额外错误检查代码。因此第一阶段预算采用本样本不超过 1.5 MB，而非承诺固定为表中精确大小。

最后一个方案的最长 payload 行为 7,785 字节。对每个实验，按引用还原成员后，成员内容与原文严格相等，5 个 SHA-256 全部一致；恢复原 bundle 后整个原始 HTML 也严格相等。原始规范产物的 `checkAtlas` 校验通过。故可在不改图内容的前提下进行格式瘦身；浏览器加载器仍须另行实现及验收。

负向检查：故意改变共享块后，还原一致性校验失败。当前文件不满足 1.5 MB 实验预算，推荐实验满足预算，避免用“没有报错”代替体积改善的证据。

## 推荐实现边界

1. **只改变图集存储格式。** 引入有版本的共享资源表；公共脚本、CSS、字体存一次，各成员保存自己的内容和资源引用。已有单图生成无需为图集另造一套 Viewer。
2. **按访问还原成员。** 只为将要打开的成员拼接 HTML，接入现有候选页面准备、就绪提交和销毁逻辑。避免启动时把所有完整页面重建并长期缓存。共享存储不会让不同 iframe 自动共享执行环境；不承诺消除每层 Viewer 初始化成本。
3. **有界字符串分块。** 使用字符串数组与 JSON 安全转义，按编码后的长度控制行宽。仅给 JSON 增加缩进不能拆开其中的巨型 HTML 字符串。还原时原样拼接，保留中文、换行、特殊字符与脚本结束标签的转义保护。
4. **保留校验和全部交互。** CLI 解包和校验先还原成员，再执行现有成员哈希、来源、导航关系和渲染检查；浏览器与 CLI 使用一致的格式约定。旧图集仍可检查，新输出采用明确的新格式版本。
5. **调整交付入口。** 调查期间不再自动打开大 HTML 文件面板；交付预览图与明确的打开入口。该措施减少触发用户已报告问题的机会，本身不是卡顿修复证据。

不把删除节点详情、离线字体、嵌套导航、主题或导出能力作为体积优化手段。第一阶段保留单文件离线交付，不增加外部 CDN 或多文件部署要求。

## 消融结果

实验验收条件：本样本估算产物不超过 1,500,000 字节，payload 行不超过 8,192 字节，所有成员及规范产物逐字节还原。

- 去掉额外的“共享 JSON 数据”处理：增加 114,268 字节，仍能满足预算和无损还原，初版方案去掉这项处理。
- 再去掉样式共享：体积回升至约 2.49 MB，不能满足预算，恢复样式共享。
- 去掉字符串分块：去重后的 payload 仍有约 1.25 MB 的单行，不能满足行宽条件，恢复分块。

未在生产生成器中增删功能。实验和测量结果留在明确标记的调查目录。

## 尚需验证的桌面端症状

已证明的是重复存储与超长行。尚未取得 Codex 应用的性能记录，不能确认冻结发生在读取文件、编辑器文本处理、HTML 预览还是浏览器 Viewer 初始化。

本机 Node 的 50 次 JSON 解析采样，中位数约从 5.25 ms 降到 1.44 ms；这不是 Codex 桌面端性能数据，不能把该差值换算成应用卡顿的改善幅度。对整个文件 gzip 后仍约 1.06 MB；对去重后的 payload gzip 再 Base64 约 0.37 MB，但这些只是存储测量，尚未验证浏览器解压和加载成本，初版不加入压缩层。

生产实现后的验收必须包括：

- 本样本最终 HTML ≤ 1.5 MB；payload 行 ≤ 8 KB；公共资源只存一份；新增层级不再重复增加公共 Viewer 字节。
- 离线打开，5 张图、三级下探、引用跳转、浏览器前进后退、节点详情、主题和原有导出检查通过。
- 保留无闪烁切换的既有验收，且页面数量仍受当前活动页与单个候选页约束。
- 同一设备、同一 Codex 版本下，对旧/新文件用相同的右侧打开方式分别记录多次从打开到可交互的耗时和应用主线程长任务，再判断是否修复用户所述冻结。浏览器预览与文件面板分别比较，不能相互替代。
