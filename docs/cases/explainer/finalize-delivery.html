Archify finalize 经过哪些模块？失败时旧产物怎么保住？

长图

答

结论

finalize 是交付编排器，本身不负责绘图。它按顺序调用 deliver → check → browser-check 三道门，只要前一道没过就立刻停下。旧产物之所以安全，是因为新 HTML 先在同目录暂存区做完渲染和自检，最后一步才原子换入目标路径。换入前会先备份旧文件，中途出错自动还原；就算还原也失败，旧文件仍留在恢复目录里。

  1. 三道门通过文件 sha256 和 receiptId 串联，确认每一步检查的都是同一份新产物。1
  2. 提交前不改动目标文件；提交时先备份旧文件再硬链接（linkSync）换新，文件身份不符立即中止。2
  3. 交付锁挡住并发写入；进行中日志只要没删掉，下次运行就直接报错，绝不盲目覆盖现场。3
  4. 保护边界在提交点：新文件一旦换入成功，后续复查失败只报错并保留诊断，不再退回旧产物。

适用于Archify @ 82c47cabin/finalize.mjs + bin/archify.mjsexplainer 默认跳过浏览器门

1

finalize 把一次交付拆成哪几道门？

图的结构
  • 解析参数与预编译 cli
  • 快照输入并准备回执 snap
  • 写入汇总回执 rec
  • 加锁并暂存渲染 del
  • 备份旧文件并换新 commit
  • 严格复查产物 chk
  • 浏览器实测（按需） brw
  • brw → rec
  • chk → brw · 校验通过
  • cli → snap
  • commit → chk · 提交成功
  • del → commit
  • snap → del

原生图默认跑满三道门；explainer 先由 prepareExplainerInput 把草稿和外部依赖打成冻结包，默认只跑 deliver 和 check，加 --browser-check 才启动浏览器实测。

  1. 解析参数与预编译 ↗

    commandFinalize 解析质量档位与输出目录；explainer 先打包冻结依赖，后续每道门前后都复核输入未变。

  2. 快照输入并准备回执 ↗

    记录输入文件 sha256，并提前锁定 .finalize.json 与摘要回执的目标路径。

  3. 加锁并暂存渲染 ↗

    获取交付锁、写下进行中日志，在同目录 .archify-delivery-* 暂存区完成渲染与自检。

  4. 备份旧文件并换新 ↗

    commitDeliveryPair 先把旧产物备份到暂存区，核对文件身份无误后再硬链接换上新产物。

  5. 严格复查产物 ↗

    核对交付凭证与新文件哈希一致后执行 check；若开启浏览器门则继续跑真实 Chrome 检查，最后写出汇总回执。

哪一步出错，旧产物会怎样？

失败阶段旧产物状态保护方式
参数错误、输入缺失或语法校验不过安全原封不动还没拿交付锁，也没向目标路径写任何文件
暂存区渲染或自检失败安全原封不动新 HTML 只写在 .archify-delivery-* 暂存区，报错退出时直接清理
原子换入中途出错安全自动还原commitDeliveryPair 从 .previous-output 和 .previous-provenance 备份换回原位并复核身份
自动还原失败，或提交中途锁丢失手工恢复留在恢复目录标记 recoveryRequired 并保留暂存目录，交给 recover-output.mjs 恢复
同一路径并发交付，或残留锁与日志安全拒绝启动报 delivery/concurrent-attempt 或 lock-stale，新交付直接停下
新文件换入后，check 或浏览器实测失败不回退已换成新产物新文件已通过 deliver 自检；finalize 返回失败并保留诊断，但不自动回退
3

一次 finalize 会在磁盘上写哪些文件？

文件作用
<out>.delivery.json交付凭证：记录 receiptId、输入与产物的 sha256 及校验摘要
<out>.delivery-pending.json进行中日志：暂存开始时写入、提交完成时删除；残留即代表上次交付中断
<out>.delivery-lock.json交付锁：阻止同一输出路径并发写入，锁异常过期时同样拦截覆盖
<out>.browser-check.json浏览器实测回执：原生图默认生成，explainer 仅在加 --browser-check 时生成
<out>.finalize.json 与 -summary.json汇总回执与精简摘要：先写临时文件，核对目标路径未变后原子换入
.archify-delivery-* 目录同目录暂存区：存放输入快照、候选产物和 .previous-* 备份；正常结束即删，需恢复时保留
