# Goal：为 Architecture Atlas 实现无损瘦身与轻量交付

在 Archify 当前开发分支实现图集公共资源去重、有界字符串分块和按访问还原成员。将固定 OpenPI 五图样本从 4,475,495 字节降到不超过 1,500,000 字节，保留单文件离线使用、完整节点详情、嵌套导航、现有导出及无闪烁切层。生成后默认交付预览图和打开入口，避免自动把 HTML 加载到 Codex 文件面板。

本文是独立的实施 goal。执行时完成代码、测试、全新生成的 OpenPI HTML、真实浏览器验收和消融记录。本文当前仅定义工作，编写本文不等于启动或完成实施。

## 1. 执行顺序

1. **固定基线。** 确认实际工作区、分支、HEAD 和未提交改动；检查本地指令及当前 CLI/交付契约。保存 OpenPI 六份输入的 SHA-256、原产物字节数、最长 payload 行和公共资源清单。先建立能拒绝超预算、成员字节变化及非法引用的测试，观察旧格式不能满足体积/行宽预算。完成条件：基线可以通过一条记录下来的命令复现。
2. **接通打包与解包。** 实现版本化资源表、成员片段引用、字符串分块及统一解码规则；接通生成、CLI 校验、浏览器启动和 visual-check 的实际入口。完成条件：新包经过真实 CLI 交付并能无损还原成员，错误包通过负向测试被拒绝。
3. **验证交互与交付。** 接入现有候选页面生命周期；更新必要的交付文档和测试，保留显式打开行为。执行下表 AC01–AC10。完成条件：最终产物通过确定性检查与真实浏览器检查，默认交付不触发文件面板打开。
4. **执行消融并收尾。** 按 AC11 逐项移除不必要设计，重跑原验收；再按 AC12 从固定输入重新生成最终 OpenPI HTML，绑定所有证据。另交付第 5 节的宿主观察记录。完成条件：AC01–AC12 全部通过，限制与测量边界明确，交付文件可直接打开使用。

## 2. 改动边界

### 本轮实施

- 图集内部打包格式与解码；公共 Viewer 脚本、CSS 和离线字体按实际内容共享存储。成员自己的图形、详情、来源、章节和导航数据完整保留。
- 新产物使用明确的新 `bundle_version`，建议 v2；CLI 继续读取并校验现有 v1 产物。Atlas manifest 的 `atlas_version: 1`、architecture schema、公开命令、地址及回执的既有含义不变。
- 浏览器只为将访问的目标还原完整成员 HTML；沿用活动页与单个候选页的准备、就绪提交、取消、失败和销毁流程。
- `deliver`、`unpackAtlas`、`checkAtlas`、`visual-check` 及离线 Skill 打包链路采用一致的格式约定。内部 API 可按需要调整，现有调用者必须迁移完整。
- 交付说明明确：默认提供 HTML 链接和已验证的静态预览；用户明确要求打开但未指定方式时使用浏览器入口，明确指定 Codex 文件面板时遵从其选择。保留 `--open` 等现有显式选项，不修改为失效或无条件忽略。
- 必要的测试、生成模板、示例、打包产物和文档更新；遵循仓库当前生成链路。

### 本轮不扩展

保留全部现有功能及样式，不通过删图、删详情、减来源或替换字体达标。维持单文件、无外部运行时依赖的交付；本轮不引入 gzip/Brotli/Base64 压缩启动器、Web Worker、CDN、多文件分发、全成员预加载、访问页面缓存或通用资源依赖图。不进行 UI 重设计、OpenPI 架构事实重写、无关依赖升级或发布部署。

本仓库不能修改 Codex 桌面端的文件查看器。文件面板自动打开属于代理交付流程，不等同于 CLI 的系统浏览器 opener；先核实实际调用链，按各自边界调整。首次调查使用的 Node JSON 解析耗时不能作为 Codex 卡顿修复证据。

### 功能保全规则

以实施前当前分支的实际菜单、快捷键、CLI、分享及导出入口建立功能清单，与最终产物逐项对照。下文列举用于指定重点验收，不是允许保留功能的白名单；未逐一列出的已有功能仍须保留。AC04 证明打包前后字节不变，还须结合此功能基线证明编译或运行时没有先删功能再打包。

功能完整性是体积预算的前置条件。若两者暂时无法同时满足，应报告预算未达标并继续优化；不得通过隐藏入口、固定降级、改变原有默认功能、降低导出质量或跳过既有回归来达标。消融只删除冗余实现，用户能力和既有状态恢复行为必须保持。本轮允许的默认操作变化仅为交付时不自动打开 HTML 文件面板；用户仍可手动或按明确指令打开。

## 3. 格式与运行时约定

| 项目 | 约定 |
| --- | --- |
| 公共资源 | 只对字节完全相同的脚本、样式和字体块去重；不同资源分别保留。使用摘要查找时仍验证内容一致，避免因同名、相同长度或分类相同而误合并。 |
| 成员片段 | 使用明确可验证的字面量片段与资源索引；资源表只含字符串块，不形成递归引用。每个成员按原顺序拼接，精确保留原 HTML 字节。 |
| 数据块 | 初版成员 JSON 数据保持原内容，不额外建立来源、翻译、节点或回执的第二套共享模型。 |
| 分块 | 按最终 JSON 安全转义后的 UTF-8 字节数分块，序列化后的图集 JSON payload 每行不超过 8,192 字节，包含缩进。覆盖中文、emoji、换行、引号、反斜杠、`<>&`、`</script>` 和跨边界字符；保留现有 HTML script 注入防护。 |
| 还原时机 | 浏览器启动只还原入口或冷深链目标；切层只还原被请求的成员。资源表和分块字符串可以随包加载；不得同时重建并持久缓存所有完整成员页面。CLI 为完整校验逐成员还原属于必要工作，不受浏览器按需规则限制。 |
| 完整性 | 成员 artifact 回执继续描述还原后的完整成员 HTML；最终 bundle 回执描述新存储格式的实际 HTML 文件。哈希是字节一致性检查，不是签名或不可信脚本的安全沙箱。 |
| 错误 | 未知版本、非法索引/类型、缺失块、无效成员、回执不匹配都产生可定位错误。CLI 交付失败不替换旧产物；浏览器格式错误复用现有首次加载或导航失败界面，不把旧图冒充目标。 |
| 确定性 | 资源和成员排序稳定；相同输入与相同生成器版本重复交付得到相同 HTML 字节。时间戳等运行记录放在外部回执中。 |

尽量让 Node 和浏览器复用同一份无环境依赖的格式解释逻辑。若必须有适配层，使用同一组有效/无效样本校验；避免两个独立解码实现逐渐分歧。格式检查不得为了方便而在浏览器启动时还原全包，也不要求引入新的全包 WebCrypto 启动门禁。

现有切换与状态规则以 [无闪烁切层 goal](atlas-seamless-navigation-goal.md) 为准：常驻工作台、访问快照、最新意图生效、历史写入资格、候选无操作/导出权限等均须保留。本轮不重新定义其就绪条件或用预加载全部页面抵消加载耗时。

## 4. 必须通过的验收

| 编号 | 完成条件及证据 |
| --- | --- |
| AC01 体积 | 第 6 节固定 OpenPI 输入全部不变，新 CLI 实际交付的 HTML ≤ 1,500,000 字节，较基线减少至少 65%。预算统计整个文件，包含启动代码、校验及所有资源；报告精确字节数和比例。此预算仅适用于固定样本，不限制任意大型架构内容的总大小。 |
| AC02 行宽 | 从最终 HTML 提取图集 JSON payload，其每行 UTF-8 字节数 ≤ 8,192，包含缩进；不用分块前字符数或 JSON 缩进代替。超长字符串和含大量转义字符的样本同样通过；旧文件触发失败。外壳其余部分记录最长行，避免新增巨型内联数据，但本轮不为无关 Viewer 源码另造格式化链路。 |
| AC03 共享与增长 | 比较同一模板的 1、5、10 成员受控样本：每份共同脚本/样式/字体只存一份；新增成员不新增这些公共块，增量由成员独有内容、元数据与引用组成。内容不同但长度相同的资源不得合并；单成员与不同资源组合仍能打开。 |
| AC04 无损 | 对真实编译出的每个规范成员执行打包→JSON 序列化→解析→还原，字节与 SHA-256 全等。覆盖第 3 节特殊字符、边界切分和恶意标签样本；还原后既有成员内容、来源、关系、章节、上下文及渲染检查全部通过。比较基准为同次编译的打包前成员，不能把新外壳的哈希误要求为旧外壳哈希。 |
| AC05 版本与错误 | 新产物明确采用新版本；v1 样本经现有校验入口仍可校验，旧独立 HTML 继续自包含运行。CLI 与浏览器均拒绝越界/负数/非整数索引、无效类型、缺失块/成员和未知版本等结构错误；CLI 另按现有完整性检查拒绝资源截断/篡改及损坏回执。不能静默丢片段或显示空白冒充成功，也不把格式升级扩展成新的浏览器签名验证机制。 |
| AC06 按需与生命周期 | 真实浏览器冷启动只还原入口或指定深链成员；导航才还原目标，未访问成员不执行。最多活动页+一个候选页，稳态只保留活动页；连续至少 20 次导航后无额外 Viewer/完整成员缓存积累，取消、失败和快速改选均正常清理。正常历史快照增长不等于页面泄漏。 |
| AC07 阅读连续 | 真实浏览器验证总图→子图→孙图→返回、引用、应用返回及原生 Back/Forward；目录、面包屑、详情/关系/源码页签、缩放/平移、章节、主题及焦点按既有规则保持或恢复。浅/深色与关闭动效均无新增空白帧、错误主题或重取景；补延迟、失败、快速改选、准备中 resize，留连续帧或视频和提交时序。 |
| AC08 离线与导出 | 新最终 HTML 在受支持浏览器通过 `file://` 和本地 HTTP 使用，不依赖输入 JSON、构建目录、网络字体或远程脚本。沿用现有 visual-check 的全部桌面尺寸，补一个窄屏。节点详情、来源、章节、搜索、route/reach/lens、主题、视觉预设、演示及既有 PNG/JPEG/WebP/SVG/WebM 导出回归通过；同时覆盖分享卡片及路径/影响范围卡片、图和卡片的剪贴板复制、节点/路径/lens/章节时刻等既有分享链接和快捷键。依据功能基线核对其他已有入口；保留各浏览器原有支持条件、输出质量、尺寸选项与失败回退。导出仍针对当前已提交成员，保留忙时导航规则。 |
| AC09 生成链路 | 必要的包格式、交付、Atlas 导航/导出/布局、普通单图和离线打包回归通过；受影响模板、示例及发布包按现有脚本生成并通过一致性检查。相同输入两次 HTML 哈希一致；失败不覆盖旧 HTML、不污染输入；发布 Skill 在无 node_modules 的既有使用场景可用。 |
| AC10 交付入口 | 默认 `deliver` 不启动 opener；代理交付默认不调用 HTML 文件面板自动打开。返回有效 HTML 链接、最终产物绑定的 PNG 预览及必要回执。显式 `--open` 的既有行为经测试保留，用户指定的打开方式仍可使用；打开失败如实报告，不影响已完成的产物校验。无需新建设置页、自动开图策略框架或常驻服务。 |
| AC11 消融 | 实现稳定后列出新增/受影响的抽象、状态、缓存或辅助层，逐个删除并重跑相同验收和功能基线。全部保持才保留删除，否则恢复；测试未覆盖的用户能力减少也必须恢复，不能仅凭测试通过接受删功能。记录候选、命令、结果及证据。体积、行宽和无损检查必须针对消融后的最终代码再次通过。 |
| AC12 最终产物 | 当前分支源码在全新输出目录重新编译固定 OpenPI 六份输入；保留 5 张图、三级路径、4 个 detail 和 4 个 reference。交付输入与生成器代码摘要、CLI 命令、成员/整包回执、最终 HTML 哈希、浏览器证据、代表 PNG 与 AC 清单。所有证据指向相同最终字节；复用旧 HTML、旧截图或旧成功回执均不能满足此项。 |

浏览器验收按现有支持范围及工具权限执行。静态截图、Node 模拟或 `iframe load` 不替代切换过程验收。必需浏览器检查受限时继续完成其他工作，报告缺失项；AC01–AC12 尚未全部通过时不将实施 goal 标为完成。

## 5. Codex 桌面端观察：单独记录，不扩大代码范围

本 goal 的完成承诺是 Archify 瘦身和交付调整，**不是修改或保证修复 Codex 桌面端**。实施时应尝试同设备、同 Codex 版本、同面板及相同打开方式的旧/新文件对照；文件面板与浏览器预览分别记录。

无法观察或采集宿主性能时，交付“未测/受限”及已尝试的方法，不把浏览器或 Node 计时替代宿主数据。该宿主观察结果不阻止通过 AC01–AC12 的瘦身目标完成，但不得宣称“Codex 卡顿已修复”。若对照仍卡顿，明确记为待解决的宿主症状，不通过本轮范围外的桌面端修改或更多新框架无限扩展工作。
