为什么 ripgrep 找不到明明存在的文本？

长图

答

结论

在 Git 仓库递归搜索时，文本可能在默认跳过的路径里。忽略规则和隐藏路径是两道独立过滤：分别用 --no-ignore 和 --hidden 检查；搜索范围变大也不能证明原来的模式正确。1

  1. .gitignore 等规则可能排除文件；--no-ignore 不会自动包含隐藏路径。2
  2. 点号开头的路径通常是隐藏路径；--hidden 不会自动关闭忽略规则。3
  3. rg 默认把模式当正则；要按原文查方括号，用 -F。4
  4. 二进制检测、搜索目录和其他过滤条件也可能影响结果。1

适用于Git 仓库递归目录搜索默认过滤

哪道过滤挡住了路径？

图的结构
  • 目录内路径 start
  • 忽略规则 ignore
  • 隐藏路径 hidden
  • 检查内容 search
  • hidden → search · 未跳过
  • ignore → hidden · 未排除
  • start → ignore
路径情况要检查的选项原因
普通路径被忽略规则排除--no-ignore不使用 .gitignore、.ignore 等规则。2
隐藏路径未被忽略--hidden包含隐藏文件和目录。3
隐藏路径也被忽略两个选项都用两道过滤都可能挡住它。23

隐藏路径有例外：忽略文件中的白名单或显式传入路径可使其被搜索。--no-ignore 也不会关闭命令行显式指定的 --ignore-file。32

2

怎样缩小范围，再查原文？

假设目标在仓库的 src 目录；先替换成你要检查的具体目录。下面查找原文 [ready]，并排除 .git 目录。-F 把方括号当普通字符；单引号也让 shell 保留这段模式。4

--hidden 可能包含 .git 等目录；扩大范围也可能读到生成文件或敏感内容，并产生大量输出。只在需要的目录运行，检查输出的分享范围。3

扩大路径范围只改变候选文件，不能证明原来的正则表达式符合意图。若需要查字面文本，请用 -F；若需要正则，请另行核对模式和预期匹配。4

3

怎样检查哪些路径被跳过？

先在同一个小目录列出候选文件，再查看跳过原因。--files 只列出会搜索的文件，不搜索内容；--debug 输出跳过信息。56

对照时，可在相同命令中逐个加入 --no-ignore、--hidden，再同时加入两者。调试输出可能很长，也可能暴露路径；不要直接公开。配置文件可改变默认选项，这里的 --no-config 用于排除配置影响。1

仍然没有结果？

确认目录和文本是否准确。递归搜索还会尝试跳过二进制文件；不要把路径已列出等同于内容一定会匹配。1
