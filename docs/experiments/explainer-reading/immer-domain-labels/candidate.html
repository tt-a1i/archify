结论

在这个例子中，Immer 只为改动路径上的根对象、tasks 数组和第一个任务换了引用。没改动的 user 和第二个任务，仍是两个版本共用的同一个对象。1

  1. 原版第一个任务的 done 仍为 false，新版为 true。
  2. 共享表示 === 为 true，不是只表示内容相等。
  3. 默认冻结会让共享对象也被冻结；“数据值没变”不代表对象仍可直接修改。2

适用于Immer 11.2.9普通对象和数组默认 autoFreeze

1

两个版本指向什么？

每个方框表示一个对象或数组，箭头表示属性引用；0、1 是数组下标。两条箭头汇入同一方框，表示它们指向同一个对象。

图的结构
  • 原版 root base
  • 新版 root next
  • 原版 tasks oldtasks
  • 新版 tasks newtasks
  • 共享 user user
  • 原版首项 false oldfirst
  • 新版首项 true newfirst
  • 共享第二项 second
  • base → oldtasks · tasks
  • next → newtasks · tasks
  • base → user · user
  • next → user · user
  • oldtasks → oldfirst · 0
  • newtasks → newfirst · 0
  • oldtasks → second · 1
  • newtasks → second · 1

共享后还要注意什么？

默认自动冻结下，这个例子的新版树被冻结。共享的 base.user 和 base.tasks[1] 也因此被冻结；不要在 produce 外直接修改它们。2

空回调、把 false 再赋为 false 这两个实测对照，都返回了原根对象：next === base 为 true。3

这张图展示的是不同版本之间的共享。单个输入应是单向树：同一对象不能在树中出现两次，也不能有环。5
