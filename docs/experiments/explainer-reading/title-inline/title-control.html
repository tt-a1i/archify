Singleflight shares one in-flight function call among callers using the same key.1

  1. Sharing is limited to one Group and overlapping calls.1
  2. A completed result is not retained as a cache entry.2
  3. Forget allows a new call to start while the old one continues.3

What happens when callers overlap?

Caller B joins A's existing call for user:42; B's function is not run. Both receive the same value and error.1

Diagram structure
  • Caller A a
  • Caller B b
  • Group group
  • Function work
  • a → group · Do user:42
  • group → work · Start A's function
  • b → group · Do user:42; wait
  • work → group · Value and error
  • group → a · Value and error
  • group → b · Same value and error

This sequence is illustrative; it shows call order, not measured duration.

Why isn't this a cache?

What is shared?An in-flight call with overlapping callersA stored result with later readers
After the call ends?Runs againThe entry is removed; a later call can run againA result may remain until eviction or expiry
Different keys?They do not join each other within the GroupEntries are typically stored per key

A cache and singleflight can work together: check the cache, then coalesce concurrent misses. Singleflight supplies no expiry or invalidation policy.12

What does Forget change?

StageWhat happens
Before ForgetCallers for the key join the existing call.
Forget(key)The Group removes the key's current association. The old function and its existing waiters continue.
A later callIt can start a new function for the same key, even while the old function runs.
Old call finishesIt deletes the entry only if the entry still points to the old call, so it does not remove the new call's entry.

The old and new calls can return different results. Forget does not cancel either call.32
