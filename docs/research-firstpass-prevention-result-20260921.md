# 首稿预防实验：覆盖映射与尺寸前置（2026-09-21）

结论：机器完成率出现 0/3 → 2/3 的探索信号，但独立审查及复核后，两组的完整质量均为 0/3。没有同质量成功配对，不能证明端到端提速或推广到默认 Skill。

## 问题与边界

目标是减少首稿语义遗漏和布局返工，包含新增准备成本；不是缩短单次校验命令。基线为 `68c94f912590aed1a1c9c2e493e2927ece639afb` 的正式 Skill、渲染器及校验器。原 dirty 工作区、正式包、live `archify` / `archify1` 和远程均保留。仅有 benchmark/helper/研究文档的本地改动。

实验条件 P 在原 Skill 上增加一份精简指南和一个初稿辅助工具：作者把原始需求条款映射到可见文字；自主选择事实、拓扑及行列；工具计算文字尺寸、列宽和相邻边标签间距，写出普通架构 JSON。它不读源码，不证明事实，不选择语义，不替作者修路由。B 只使用原 Skill。组合实验不能把效果单独归因于覆盖表、字体测量或行列布局。

先冻结三项原有任务、源码提交、模型和成功门槛，再进行六次串行新作者试验。全部作者是 Terra / medium、独立新上下文，600 秒原生任务上限，第一次 finalize 后最多三次修复；不替换失败样本，不修改任务，不放宽质量。任务是已知开发案例，不是未见仓库验证。原型只改了两版；第二版修复输出祖先目录软链接逃逸。首位作者派发前另有一次已记录的 observer 行尾空格清理，冻结记录保留修改前后的哈希。

## 六组结果

下表的“首稿”指第一次观察到结构完整 JSON，不表示语义或视觉正确；“首稿后”包含后续检查、修改和最终回复。所有耗时单位均为秒。

| 任务 | 条件 | 首稿 | 首稿后 | 作者总时 | 含准备/派发总时 | 校验前内容修改 | 失败 finalize 后已观察修复 | 最终机器通过 |
|---|---|---:|---:|---:|---:|---:|---:|---|
| p-retry | B1 | 168.5 | 145.9 | 314.4 | 323.1 | 0 | 3 | 否 |
| p-retry | P1 | 196.3 | 99.4 | 295.7 | 309.2 | 1 | 0 | 是 |
| quick-lru | P1 | 162.9 | 91.0 | 254.0 | 266.0 | 0 | 2 | 是 |
| quick-lru | B1 | 174.0 | 115.4 | 289.5 | 298.0 | 0 | 3 | 否 |
| lilconfig | B1 | 219.8 | 123.8 | 343.6 | 352.2 | 0 | 2 | 否 |
| lilconfig | P1 | 213.9 | 156.7 | 370.6 | 580.3 | 0 | 3 | 否 |

三项 B 最终机器通过 0/3，P 为 2/3；六组初稿静态校验全部失败。p-retry-P1 在第一次 finalize 前已经修过一次，所以“首次 finalize 通过、之后修复为零”绝不是一次成稿。lilconfig-B1 作者文字声称三次修复，但观察到三个候选和三次 terminal finalize，公共调用记录也只有三次；因此仅记第一次之后两次已观察修复，不采用自报数。

lilconfig-P1 的准备至原生作者启动间隔为 209.7 秒，其中实际复制准备约 0.6 秒；这一派发间隙发生于本会话上下文交接期间。其余五组准备/派发为 8.5–13.5 秒。按预先口径，580.3 秒完整耗时照实保留，不事后减去调度成本；370.6 秒作者耗时另外展示。六组 observer 均未过期，最大轮询间隔 0.147 秒以内，仍不保证捕获极短暂的写入。

原始完整耗时是完成或失败的耗时，不是六个成功交付样本。B 没有合格机器交付，因此至少两对同质量成功样本这一门槛已不可能达到。合格配对数为零，不计算提速百分比，不启动预设的反序确认，也不推广安装。

## 独立质量审查

两位审查者只收到打乱编号的 12 个首稿/末稿案例、固定源码、原始条款和实际截图，看不到条件、耗时或彼此的审查结果。失败机器候选没有截图，其视觉状态为未知；不能因此说画面质量已失败或通过。

| 最终状态 | B | P |
|---|---:|---:|
| 完整机器门槛通过 | 0/3 | 2/3 |
| 源码语义审查通过（复核后） | 2/3 | 2/3 |
| 完整机器＋语义＋视觉接受 | 0/3 | 0/3 |

初审两位都把语义判为通过，但主审检查发现 pRetry 的关键条件未明确表达：`index.js:124–137` 在回调前重试时间已经耗尽时，仍执行 `onFailedAttempt({retryDelay: 0, ...})`，跳过 `shouldConsumeRetry` / `shouldRetry` 后抛错。原始第 3 条已要求实际顺序及条件；这不是新增隐藏条款。用同一问题复核全部四个 pRetry 首稿/末稿，两位审查者都修正为语义未通过。P 的失败决策视图还泛称失败后先决定 consume，限定正常剩余时间路径的卡片没有讲清这个分支。原始初审、定点复核和错误引用修正均保留，不能把初审一致当作语义真值。

对两张 P 最终截图，Luna 认为可接受，Terra 认为 1440×900 默认视口的密集连线小字不够可靠、较大视口才清楚。主审复看同样的 1440 亮/暗图后，认同阅读负担问题，因此不认定视觉接受。这里是记录了分歧的视觉判断，没有修改机器字号下限；正常向下滚动卡片不是失败理由。即便接受较宽松的视觉意见，也仍没有 B 的机器成功配对，不改变不提速、不推广的结论。

所有六个首稿的原静态门槛均失败，完整首稿通过率 0/6。覆盖映射没有在这轮提高源码语义通过数；保持首稿文字不变，也会把首稿里的遗漏一直保留到末稿。

## 哪些机制有信号，哪些仍无效

P 的两个最终产物跨过了原来的完整机器门槛，且它们从首稿到最终稿没有非几何字段变化。这是可继续研究的完成率信号，但每项只有一位作者，不能证明稳定因果收益，更不能绕过语义及视觉审查。三个 P 的所有首稿到末稿内容投影均相同；p-retry-B1 删了四条返回/取消连线，lilconfig-B1 缩短了 Caller 副标题（移除 supplies options，其独立 options 节点仍在）。这些变化完整保留，是否损害表达由源码审查判断，不能只看 JSON 不变或边数。

尺寸预检的缺口已经明确：工具只输出估计，不强制可用视口预算。p-retry-P1 首稿经渲染得到的 viewBox 宽 2137，1440 视口下边文字投影约 5.04px；QuickLRU-P1 宽 3226，投影约 3.34px，均低于原校验的 6px 下限。工具自己的保守副标题预估已分别只有 5.47px、2.57px，但没有阻止生成。lilconfig-P1 同样报告 2.42px 的保守预估，其校验先被路由缺陷挡住。这里验证的是“测到了但未约束”的问题，不能声称尺寸前置已解决可读性。

lilconfig-P1 初稿先有自动路由 micro-segment，后续调整出现短内段、桌面可读性以及标签/路径碰撞，三次修复后仍失败。B 的最终阻塞分别是 p-retry 标签/路径间距、QuickLRU 标签/路径间距，以及 lilconfig 穿节点和交叉。行列尺寸合理并不能保证实际路由可行，局部尺寸、整图缩放和完整拓扑是耦合的。

## 大头成本及观测边界

六个作者原生执行合计 1867.6 秒（31.1 分钟）。首稿需 162.9–219.8 秒，首稿后仍需 91.0–156.7 秒。每组所有已观察 finalize 的机器执行合计仅 1.3–4.0 秒；失败 finalize 大多止于 validate，不能拿它们与完整成功流程作性能比较。公共工具调用外层耗时合计为每组 3.4–20.3 秒，这也不是剩余全部时间属于思考的证明。现有证据只能定位到作者理解、组织、生成和修改的分钟级流程，不能分解隐藏推理、供应商排队和网络重试。

没有观察到公共 native error 事件；这不证明模型生成途中没有网络重试。保存的是开始/结束时间、粗粒度工具类别、实际 JSON 版本和校验结果，不包含隐藏思维链和原始工具参数。截至证据封存前，本轮记录的研究墙钟时间为 72.2 分钟，包含原型、实验、后验评估和审查；六位作者原生时间单列为 31.1 分钟。各阶段时间戳保留，不把研究总时当用户交付耗时。

## 后续方向与本轮决定

保留这次冻结原型和失败证据，不把它升级为默认 Skill。下一项值得验证的假设是：在完整语义不变的前提下，让实际全图视口预算成为首稿布局约束，并在首次成稿前联合检查所有路由；不能只打印尺寸提示，也不能靠删节点/分支达标。另一项需要单独对照的假设是：把源码中会改变后续行为的条件分支转成可核对的事实，再检查图上的条件与路径；字符串存在不是语义覆盖。两项应拆开测，避免再次无法归因。这些是下一轮假设，本轮不追加第三版原型或更换任务来追求通过。
