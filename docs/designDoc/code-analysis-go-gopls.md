# Go 功能替换与 gopls 能力清单

日期：2026-11-12。基于当时最新 `origin/labs/code-analysis`：`197980b7`，分支 `codex/code-analysis-go-gopls`。这是本地实现与验证记录，尚未合入或发布。

**后续实现更新：已选择并接入官方库路线。** 结果见 [官方库实现与修复](code-analysis-go-official-implementation.md)，决策依据见 [维护成本对照](code-analysis-go-official-vs-gopls.md)。下文保留早期 gopls 混合实验和扩展能力盘点；该实验同时运行 gopls 和辅助类型检查，已不作为产品运行时。

| 路线 | 语义能力由谁负责 | 我们承担的成本 |
| --- | --- | --- |
| A：使用 gopls | 包/符号/引用/实现等查询以 gopls 的公开接口为准，不另跑一套类型检查补同一项查询 | 安装与版本兼容、进程和 LSP 生命周期、结果到 Archify 证据的转换；公开接口缺少的现有字段必须明确列为缺口 |
| B：使用 Go 官方库实现分析器 | 用 `go/packages`、`go/types`、AST 和所需的官方公开工具库，查询和证据组织由 Archify 负责 | 工具库版本、工程加载边界、查询实现、错误恢复及回归维护；没有 gopls 可执行程序和 LSP 服务依赖 |

这里的单一语义来源，与指标/哈希/输出格式等产品代码分开计算。若 A 的“完全使用”还要求完全不遍历 AST，则当前复杂度和嵌套等指标也存在公开接口缺口，不能继续承诺全功能等价。任何现有功能的删减都需要单独决定。

B 应具体参考 gopls 的包与测试变体选择、定义对象定位、方法集查询、部分错误处理和快照一致性；按批量分析需求选取设计，不先引入它为交互编辑服务的大型缓存和会话体系。依据本轮核对的 gopls 0.21.1 源码：

- [cache/load.go](https://github.com/golang/tools/blob/gopls/v0.21.1/gopls/internal/cache/load.go)：使用 `packages.Load`，并处理模块、文件等不同加载范围。
- [golang/definition.go](https://github.com/golang/tools/blob/gopls/v0.21.1/gopls/internal/golang/definition.go)：选择适合文件的包变体、定位 AST 节点并组织声明查询。
- [golang/implementation.go](https://github.com/golang/tools/blob/gopls/v0.21.1/gopls/internal/golang/implementation.go)：按方法集或函数签名查询，组织局部类型检查、跨包索引与结果去重。

参考设计时，运行时依赖应落在 Go 的公开 API；直接导入或复制 gopls 的 internal 实现会带来另一套跟随上游的维护成本。两条路线都要以相同功能、捕获范围、错误样例与真实项目验收，比较安装、冷启动、耗时、内存、代码责任和后续功能成本，不能只比文件行数。若其中一条无法满足某项要求，应如实记录缺口，不能通过混用补齐后再宣称单一路线等价。

按约定分三部分：先保留并替换当前 Go 功能，再核对 roadmap 缺口，最后列额外能力。后两部分只列建议，没有接入执行。

## 1. 当前功能的替换结果

该实验曾用 gopls 的 LSP 定义查询提供包和调用目标；当时删除了旧的逐调用目标解析路径，没有失败后退回旧解析器的开关。实验事实标记为 `go-source-direct-v5` / `gopls@版本`；当前产品已使用 v6 官方库模型。

| 最新代码已有的功能 | 实现与保留的行为 |
| --- | --- |
| 根模块和源码选择 | 模块指令改用 `go mod edit -json`，补齐 block 与 Go 字符串转义。平台、tags、测试、排除项、嵌套模块边界保留。 |
| 包依赖图 | gopls 返回导入包的位置，再映射为捕获的生产文件成员；保留包名与目录名不同、别名及外部依赖未知状态。 |
| 函数与具体方法调用 | gopls 返回声明锚点，映射为已有函数范围；保留跨文件、跨包、别名、提升方法、泛型实例、方法表达式。 |
| 接口调用与实现候选 | 保留接口声明绑定、外部嵌入方法、完整接口满足关系、值／指针区别和提升证据。候选仍不表示运行时目标。 |
| 度量与源码证据 | 保留复杂度、嵌套深度、UTF-16 范围、哈希及匿名函数处理口径。 |
| 问题与变更查询 | 保留函数入口、直接调用者、变更定义引用、接口候选、测试角色和证据过期检查。 |
| 图规则、C6、C7、AI 任务 | 继续消费同一份事实；没有改规则口径、重复检测器、外部诊断入口或任务生成器。 |
| 旧结果与失败路径 | v1–v4 保存结果继续可读；缺少 gopls 明确失败。新增初始化能力检查、超时、关闭与退出清理。 |

**不能说“gopls 完全替代整个 Go 提取器”。** 公共 LSP 没有返回现有复杂度指标，implementation 的位置列表也没有完整的 `T` / `*T` 满足关系与提升细节。因此保留：

- Go 官方 `go/parser` / `go/ast`，以及 Archify 的指标、坐标和源码证据投影。
- Go 官方 `go/types`，以及原有捕获包、测试变体、SDK 导出类型装配，供方法集与歧义检查使用。
- Archify 的范围控制、候选含义、历史结果读取和来源校验。

剩余类型装配仍有维护成本，而且与 gopls 存在部分重复类型检查；本轮没有把它伪装成已经全部删除。它不再负责逐调用选目标。仅为删除这部分而放弃现有接口证据，会违背本次保留功能的要求。

该实验曾新增 gopls 和 `vscode-jsonrpc@10.0.0`。验证组合为 Go 1.26.2、gopls 0.21.1、Node 20.20.2、macOS arm64。每次分析启动一个服务，不增加常驻服务或连接池。这些运行依赖已移除；当前配置和失败语义见 [Go 使用说明](../../archify/modules/code-analysis/docs/GO.md)。

### 范围和成本

gopls 只读临时目录中的捕获源码。该目录保留 module 和 Go language version，不加载第三方 require、replace、go.work、vendor 或嵌套模块；关闭模块下载和自动工具链下载。这保持原来的单模块源码范围，**不等于已经完成真实工程依赖加载**。gopls 会运行包加载命令，但不执行被分析项目的程序、测试或生成器。

`go.stdlib: false` 仍保留原来的调用准入及接口证据口径，并关闭辅助检查器的 SDK 导出准备；gopls 自身仍会使用 SDK 类型。两者的来源分别记录，不能把辅助检查器的 disabled 解释成整个进程没有读 SDK。源码缺依赖与查询失败保持可见；“零目标”不是完整性证明。

### 验证

- 替换前：同一基线的 24 项 Go 回归全部通过。
- 替换后：保留这 24 项行为断言，仅更新新 producer/model 的预期；新增捕获隔离、模块语法、历史结果、缺失服务器、卡死清理、崩溃和不兼容坐标的测试。
- Go、比较口径和 adapter revision 的聚焦回归：43 / 43 通过。
- 完整模块回归：606 项，590 通过、16 个真实 jscpd 用例因未设置工具路径跳过、0 失败。随后安装独立临时 jscpd 5.4.3，补跑上述全部跳过项与 Go 替换回归：54 / 54 通过，0 跳过，包含 Go 重复检测及双位置任务证据。
- Archify 顶层 `serve/check/task` CLI 路由冒烟通过；未重复它包装的整个模块套件。
- 尚未执行远端 CI、原生 Windows/Linux 或发布 ZIP 验收；不把本机结果称为发布就绪。

三个真实项目使用相同源码、配置和 SDK，对照 `197980b7`。均关闭测试文件，保持原有第三方依赖未加载范围。

| 项目 | 文件 / 函数 / 调用 | 已绑定目标：前 → 后 | 库存、指标、导入边、接口边、已有目标 |
| --- | --- | --- | --- |
| chi v5.5.0 | 36 / 225 / 827 | 234 → 234 | 相同 |
| Cobra v1.10.2 | 18 / 269 / 1,468 | 721 → 721 | 相同 |
| x/mod v0.43.0 | 22 / 381 / 2,059 | 628 → 628 | 相同 |

共 4,354 个调用，gopls 查询失败为 0。最终对照也逐项核对了 receiver/interface/directCaller 字段，忽略 JSON 对象键顺序后相同。该证据证明这组输入保持既有结果，不证明未知调用全部可解。最后一次实测前/后耗时分别为 1.16/1.44 秒、0.57/1.14 秒、0.68/1.47 秒；缓存未做冷启动控制，只说明本轮增加了成本，不作为稳定性能比率。原始统计见 [验证数据](code-analysis-go-gopls-evidence.json)。

### 消融与简化

删除了预留但未使用的 references/typeDefinition/implementation 请求白名单、未消费的诊断缓存，以及只有一种查询时的通用 Set 分发；移除后核心回归仍通过。没有加入双后端、后台连接池或自动修复执行层。尝试只按 gopls 返回位置接纳结果时，泛型约束调用越过了现有“未知”边界；原有负例失败，因此恢复该范围门槛。指标与方法集适配保留，因为现有消费者依赖它们且公共 LSP 无法等价提供。

## 2. 对照 roadmap：还需要补什么

依据 [roadmap](code-analysis-roadmap.md) 和 [产品计划](code-analysis-product-plan.md)，以最新代码校正旧文档状态：C6 重复检测、C7 诊断导入、集中度规则以及变更查询已经有实现，不能继续写成从零开始。以下均为待选项。

| roadmap 目标 | 当前基础与真实缺口 | gopls 能提供什么 | 建议 |
| --- | --- | --- | --- |
| C7 规范诊断 | 已有 `lib/external.mjs`、导入契约与任务证据；尚无 gopls 诊断来源适配 | 编译前端错误、Go 分析器诊断；映射到现有导入契约 | **下一优先项**。保留 source/code、版本、范围、完整性、证据哈希及去重；不能把第一批通知当成完整扫描。 |
| 变更影响 | 已有捕获的直接调用者、接口候选和前后定义比较；未覆盖一般符号引用 | `references` 可补类型、字段、常量、函数取值等非调用使用 | **建议补**。区分使用位置、直接调用、接口候选，不能把 references 全塞进现有 caller 数量。 |
| 修改后验证 | 已有重分析、可比性和证据失效；完整行为验证仍需项目测试/lint/typecheck 回执 | 修改前后诊断可作为一项证据 | **配合验证回执阶段做**。无诊断不能替代构建、测试或证明修复。 |
| 阅读路径与影响探索 | 已有函数调用记录；完整路径交互尚需产品设计 | incoming/outgoing call hierarchy | **后置**。它是静态线索，不补全动态调用；先验证 references 的实际价值。 |
| C6 重复与目录组织 | C6 已用 jscpd；组织、边界、集中度依赖产品规则和真实项目校准 | 没有等价的重复/架构规则输出 | **继续现有路线**，不为接 gopls 重做这些模块。 |
| 图与代码一致性、忽略理由、筛选、用户试用、多语言 | 属于图映射、证据、交互和其他语言适配 | 不能由 Go 语言服务器直接完成 | **仍按 roadmap 推进**，不能把接入 gopls 当成这些目标已完成。 |

本轮只启动 definition 查询。诊断导入、references、call hierarchy 都未启用。

## 3. gopls 额外提供、我们可能需要的能力

这些能力不因官方提供就默认进入产品；表中优先级是建议。

| 能力 | 对 Archify 的可能价值 | 是否建议接、需要的边界 |
| --- | --- | --- |
| Hover：签名、类型、注释、文档链接 | 源码阅读和 AI 任务补充语义上下文 | **可选，较有价值**。按需展示，保留来源，不把说明文本解析成确定的绑定事实。 |
| documentSymbol / workspaceSymbol | Atlas 或搜索定位类型、字段、常量等 | **可选**。当前锚点以函数为主，先确认是否扩展到这些符号。 |
| typeDefinition | 从变量跳到类型定义 | **可选**，适合源码阅读；无需先做完整编辑器。 |
| implementation 双向导航 | 从接口看实现、从具体类型看接口；探索更广的候选 | **可选补充**。当前已有精确方法集证据；要防止丢失值/指针区别，也需验证泛型和跨包边界。 |
| Rename / extract / inline / implement-interface / quick fixes | 给 AI 或用户提供可审阅的候选 diff | **后置到验证回执之后**。先预览，再由明确操作应用；命令式 code action 可能产生副作用，不能当纯查询运行。 |
| organizeImports / formatting | 在用户接受改动后整理 Go 文件 | **低优先级**。编辑器已有成熟入口，与当前源码调查目标重叠有限。 |
| 补全、signature help、semantic tokens、inlay hints | 嵌入式代码编辑体验 | **暂不接**。当前产品是架构和源码调查，没有承担完整编辑器职责。 |
| 编译器优化细节：逃逸、内联等 | 针对性能问题提供线索 | **按真实性能需求再做**。依赖可构建的工程环境，也不能代替 profiling。 |

资料为官方功能文档。除本轮接入的 definition 外，表中能力未逐项在所钉版本上验收；选中后需确认该版本能力、配置和真实输出，不能直接按最新在线文档调用。
