# 路径、地图、透镜互斥切换

状态：**实现、浏览器验收、实施消融和最终 Node 门禁完成。** 修改保存在 `codex/canvas-visual-polish` 本地工作区，未提交或推送。

## 用户决定与行为

用户明确要求“都改成互斥”，范围为工具栏的路径、地图、透镜三个入口。此前路径与地图可共存，打开未选择类型的透镜面板也不会退出路径，三个按钮的激活状态容易混淆。

现在启动任意一个工具都会退出其余两个，包括空透镜面板、已生效类型选择、路径选点和已完成路径。按钮、快捷键、图例及相应能力入口使用同一套清理调用，切换保留当前镜头。退出工具时清理旧选择、运行状态、面板和不再有效的分享 hash；恢复路径深链接时显式保留传入 URL。

沿用三个模块现有的 `clear`／`close`，没有增加模式管理器、工具栏选择状态或持久化。搜索、帮助等入口不属于本次三者互斥范围，关闭当前工具本身的原有行为继续保留。

## 验收

新增 `navigation-modes-browser.test.mjs` 并纳入统一浏览器门禁：

- 原生点击覆盖六种有向切换，逐次检查活动状态、按钮状态和可见面板只属于一个工具，并核对镜头完全一致。
- 已选透镜切换到路径／地图后，无残留筛选或分享 hash；已完成路径切换后，无残留路径或播放状态。
- R／M／L 快捷键、快速连续能力调用、直接类型选择、路径深链接恢复均覆盖。
- 修复前测试实际捕获路径／地图同时激活等失败。最终定向套件 14 项通过，0 失败、0 跳过。
- Maka 原输入以原生点击执行“路径 → 透镜 → 地图 → 路径”，状态互斥且镜头不变；三个状态截图已实际审阅。私有图与详细观测保留本地。

## 实施消融

`prepareForLens()` 与 `open()` 都会关闭地图，看似重复。在隔离产物中删除前者的关闭调用后重跑原验收，12 项子用例通过，但“直接选择类型而不打开面板”的用例失败：地图和透镜同时激活。恢复并保留这处清理；两个入口服务不同调用路径，没有新增抽象需要保留。
