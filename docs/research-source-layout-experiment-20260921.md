# 源码理解与首稿布局：工具实验（2026-09-21）

> 已完成 8 次计时作者任务与 2 次独立质量评审。本轮没有证实可推广的等质量端到端提速，保留全部失败与负结果。

## 当前结论

- 源码理解：工具可用性不等于节省理解工作。Polka 的 outline 诊断单对没有加速；lowdb 的交互工具组未实际成功调用。预置索引的完整 lowdb 作者较慢，但其语义比缺失必要内容的基线完整，不能作等质量速度百分比。
- 首稿布局：内容感知尺寸通过本地 fixture，却在完整 Polka 样本触发路由短折线；回退后仍未交付。固定行列的七组间距搜索也没有解开该反例。
- 保留实验工具与证据，不将这两种机制接入默认 Skill。下一轮优先研究带精确证据范围的定向符号导航，以及考虑路由约束的布局/几何修复；均仍需新样本对照。

## 问题与约束

目标是降低源码探索/语义理解和首稿布局的大头耗时，保留事实、来源、视觉可读性和完整交付门槛。工作基于 `104b92baf1aaed865b41a3d13ee645a82684e0e2`，未改 live Skill、产品实现、用户原工作区或远程分支。

两个窄机制：`ast-grep 0.45.3 outline` 的静态导航集成；内容感知的离线网格尺寸辅助。研究过 Aider RepoMap、TypeScript Compiler API、Serena/LSP、SCIP；后四者本轮未执行，不把源码研究当试用。选型分析见 [工具研究](research-source-tools-20260921.md)。

作者统一为 Codex 原生 `gpt-5.6-terra / medium`，全新上下文、串行运行。每次上限 600 秒，最多三次完整出图修复，无整轮重试。隔离靠独立目录和读写指令，不声称模型工具由 OS sandbox 强制隔离。使用已知公开任务而非未见留出集；各机制每任务仅一对，不可推断总体平均收益。操作系统缓存和服务端排队未受控。

固定目标：Polka `c36cf8b5d1a57164e64fdd7d4e0d0f80ab262dc0`，lowdb `8a6fce9b72f769b22533f0979fbc2e73180f8112`。任务和此前完整源码 rubric 原样保留，禁止按节点数量压缩语义。初稿与最终稿分别评审。

只提取公开运行记录中的模型/档次、任务时间、工具种类与调用耗时、公开错误事件和上报用量；不导出模型推理、原始工具参数/输出。无法由这些记录区分服务端排队、隐藏 HTTP 重试和内部请求耗时。无公开错误不等于没有网络问题。

## 源码理解诊断（已完成）

该任务产物是带来源的事实 JSON，不含几何或 HTML，不能当完整出图性能。耗时包括探索、事实整理、JSON 编写和最终消息；不是纯模型语义推理时间。

## 完整出图对照

条件在作者启动前冻结：lowdb I（索引直接随任务提供）→ B；Polka B → L（网格辅助）。I 是新的集成机制和完整任务，不与上述 O 诊断结果混池。L 仍由作者选择行列/相对位置，只调整尺寸、间距和画布，不能替代语义布局决策。

所有完整任务的第一稿都未通过机器门槛。I 的四版候选前三版均有来源行号越界；B 的 lowdb 候选经历桌面字号、节点间距/短线段修复。Polka B 修复短线段后通过；L 从文字宽度问题修到桌面字号仍未通过。逐版原字节复验已保存，不能以“JSON 已写出”冒充首份合格产物。

首份后来通过全部验收的候选成形时刻：lowdb I 287.621 秒（含 0.083 秒索引），Polka B 230.823 秒。这是候选字节写出时刻，完整交付/作者结束分别为上表时间；独立事后评审时间不计入作者关键路径。lowdb B 和 Polka L 在给定额度内没有满足完整质量门槛的结果，不报告其合格交付延迟。

隐藏条件/耗时的 Luna/high 评审：lowdb B 缺少默认数据、保留的内存状态与读取替换行为；lowdb I 的说明覆盖这些职责，视觉也更完整。因此这对的较短基线不能用来计算等质量提速或减速。I 的索引已随任务提供且任务被读取，但无法观测模型内部实际使用程度。

Polka L 没有说明请求上的 path/query 暴露行为，机器终态另有 `composition/desktop-readability`：1440×900 下 onNoMatch 辅助文字投影 5.80px，低于 6px 门槛。辅助本身先因 middleware-error 的 14/15px 内部折线返回 declined；最终是普通回退流程的失败，不能说是辅助输出通过。

评审也有边界：lowdb B 的浏览器存储部分位于首屏以下，截图不能证明永久 SVG 裁切或 HTML 丢失；本报告记为默认视口概览不足。Polka L 无需独立 parser 节点，缺的是 path/query 的意义而非指定节点数量。评审文字中的几处来源范围超出文件长度，协调者按实际文件修正引用并保留原评审和单独裁决，未悄悄改写结论。

见 [原型研究与边界](research-layout-advisor-20260921.md)。现有默认网格在 starter/web-app 上通过，但 production-deployment 区域重叠、长 CJK 标签溢出；离线辅助使这四个本地 fixture 通过现有 showcase 验证。匹配的 source-backed fixture 需正确 `--repo-root`，缺 root 拒绝。坐标固定的连接、非法/重复组件 ID 等拒绝处理。只在完整验证 receipt 与候选哈希绑定时返回 advised。

原型输出不等于交付：production 和长 CJK 样例另经正常 finalize 四个门槛通过；production 的 1440×900 浅色截图已人工查看，无明显重叠，内容较密，不能由这些毫秒级本地检查推导作者收益。

## 后续离线追查与取舍

完整作者任务冻结后，在同一份 Polka L 初稿上预注册七组间距，保持源码事实、行列、标签和连接不变，以生产路由/验证择首个通过项。正确 repo-root 下 3.071 秒全部失败，仍为相同短折线；无成功候选。前一次协调调用错误使用本地 origin 的 clone，2.467 秒因 origin-mismatch 拒绝，单独保留配置错误。没有追加或替换任何计时作者。

这支持收窄下一轮方法：

1. 小仓库继续按问题读源，避免默认全仓摘要。符号别名/跨模块歧义确实阻碍探索时，再测定向 definition/reference 查询及带准确行号的证据片段；大仓库冷热缓存分开算。不能预先假定 TypeScript/LSP 有收益。
2. 让确定性工具负责尺寸、线路和证据范围校验，研究从失败诊断生成局部几何修复。固定行列加大全局间距已不足，应考虑连接进出方向、障碍绕行和全图可读性约束。D2/ELK 一类布局机制值得按这些约束评估，不能直接替换后宣称成功。
3. 仍用同任务、同模型、同门槛比较合格交付。当前每机制仅一个完整对照，下一轮需新的任务/复杂度分层，禁止在已见反例上调到通过后称为泛化收益。
