# Architecture Atlas 轻量开发流程

Architecture Atlas 仍处于试验阶段。当前目标是允许高频迭代，同时保持 `main` 随时可发布。

## 分支职责

- `main`：稳定、可发布的主干，不直接承载未完成的试验功能。
- `integration/architecture-atlas`：Architecture Atlas 的长期集成分支，汇集已通过局部验证的功能改动。
- `feature/atlas-*`、`fix/atlas-*`、`perf/atlas-*`：短期工作分支，通过 PR 合入集成分支，合入后删除。

## 阶段一：持续迭代

1. 从最新的 `integration/architecture-atlas` 创建短期工作分支。
2. 在工作分支完成实现、相关测试、生成物更新和必要文档。
3. 通过评审与分支级验证后合入集成分支。
4. 保持一张从集成分支指向 `main` 的 Draft PR，让范围、风险和 CI 状态持续可见；此阶段不合并。
5. 定期将 `main` 同步到集成分支，并及时解决冲突。至少在准备 RC 前完成一次同步和完整回归。

## 阶段二：RC 冻结

满足以下条件后进入 RC：功能范围冻结、已知阻断问题清零、文档和生成物完整、完整 CI 通过。

1. 停止加入新功能，只接收阻断发布的问题修复。
2. 在集成分支创建 `atlas-rc.N` 标签，记录对应提交、验收结果和遗留风险。
3. 对候选版本执行完整回归、真实项目生成、浏览器交互和发布包验证。
4. 修复后递增 RC 编号并重新完成全部门禁，直到达到发布标准。

## 发布

1. 将 Draft PR 转为 Ready，并完成最终评审。
2. 合入 `main`，按项目正式版本规则发布。
3. 删除已合并的短期分支；集成分支可在发布后归档或基于最新 `main` 重建，用于下一轮试验。

## 验收门禁

- 每次合入集成分支：相关单元、契约和浏览器测试通过，生成物与源码一致。
- 每次同步 `main`：冲突已解决，完整 `npm test` 通过。
- 进入 RC：CI 全部通过，真实项目架构图可从空目录重新生成，核心交互、导出和离线使用无回归。
- 合入 `main`：RC 验收记录完整，无阻断问题，Draft PR 已转为 Ready 并获批准。
